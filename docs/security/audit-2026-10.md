## Как проверяли

- Матрица `маршрут → middleware → FormRequest::authorize → политика/скоуп → сервис → репозиторий` по каждому модулю.
- Grep по классам: `whereRaw|orderByRaw|selectRaw|havingRaw|DB::raw|DB::select|DB::statement`, `like`, `fill(`,
  `$guarded`, `Log::`, `Http::`, `innerHTML`, `bypassSecurityTrust`, `eval`, `postMessage`, `chrome.storage`.
- **Регрессионные тесты прогнаны на коде `origin/main`** (отдельная копия, свой `vendor`, MySQL 8.4): они **падают**
  (доказательство уязвимости), на ветке с исправлениями — проходят. Ниже — фактический вывод.

## Процедура: красный `composer audit` / `npm audit` в CI

Job `security` падает, если `composer audit --locked` находит advisory или `npm audit --audit-level=high` — уязвимость
high/critical (frontend, extension). Порядок реакции:

1. **Обновить пакет** в отдельном PR (`composer update <vendor/pkg> --with-dependencies` / `npm update <pkg>` или
   `overrides` для транзитивной зависимости), зелёный CI, обычное ревью. Это путь по умолчанию; срок — 3 рабочих дня
   для high/critical.
2. **Временное исключение** — только если исправленной версии нет или уязвимый код не достижим в SinHRM:
   - composer: `config.audit.ignore` в `backend/composer.json` с ID advisory;
   - npm: `overrides` на безопасную версию, а если её нет — ID advisory в отдельном файле исключений рядом с job и
     фильтр в шаге;
   - в том же PR запись в этот раздел: **ID, пакет, почему не достижимо, дата пересмотра (≤ 30 дней), владелец**.
3. Просроченное исключение снимается; если пакет так и не обновлён — решение о замене пакета за владельцем модуля.

## Оставшиеся риски и владелец решения

| # | Риск | Почему не закрыт кодом | Владелец |
|---|---|---|---|
| R1 | **Права пользователя MySQL.** Миграции идут через `/api/ops/migrate` тем же логином, что и приложение, поэтому у него есть DDL (`CREATE/ALTER/DROP`). | R2 | **TLS к MySQL не обязателен.** Без `MYSQL_ATTR_SSL_CA` соединение без шифрования. | Зависит от сетевой схемы целевой площадки (локальная сеть / облако). | DevOps IT STEP: задать CA или подтвердить изолированную сеть |
| R3 | **Preview-деплой исполняет код ветки PR с секретами Vercel.** Ограничено ветками этого репозитория и меткой `preview`; Vercel сейчас заморожен (`VERCEL_DEPLOY_ENABLED`). | Принцип работы preview; закрывается только отказом от preview или отдельным preview-токеном без доступа к prod. | Владелец репозитория (zapleoceo) |

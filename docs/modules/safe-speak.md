# Модуль SafeSpeak (анонимные сообщения)

## Что это и зачем
Иногда сотрудник хочет сообщить о проблеме — травля, дискриминация, мошенничество, опасность на рабочем месте — но
боится последствий. **Safe Speak** принимает такие сообщения **анонимно**: система не хранит, кто написал, с какого
адреса и из какого браузера. Вместо имени автор получает **код доступа** (показывается один раз): по нему он читает
ответы и дописывает. Читают и отвечают только специально назначенные администраторы — **обработчики**.

## Как пользоваться
- **Сервіси → Safe Speak** (`/safe-speak`): категория, тема, что произошло → «Надіслати». Появляется код вида
  `XXXX-XXXX-XXXX-XXXX` — его нужно сохранить (восстановить нельзя). Вкладка «У мене є код» — ввести код, увидеть
  ответы, ответить. Форма работает и для вошедшего пользователя — сервер его всё равно не узнаёт (см. ниже).
- **Суперадмин → Користувачі**: кнопка «Зробити обробником Safe Speak» у суперадмина/админа
  ([users.md](users.md)). Для рекрутера/наблюдателя флаг не ставится (422).
- **Адміністрування → Вхідні Safe Speak** (`/safe-speak/inbox`): список, ветка, ответ, статус (`new` → `in_review` →
  `closed`). Без флага обработчика — 403 даже админу.

## Как устроено
- Счётчик в меню ([shell.md](shell.md), `GET /api/nav/badges`, [core.md](core.md)): `Services/SafeSpeakNavBadges` — ключ `safe_speak` («Вхідні Safe Speak», только обработчики — тот же gate `safe-speak-handle`): новые обращения (статус `new`), которые ещё никто не взял. Ничего об отправителе не раскрывается — это просто число.
Бэкенд — `backend/app/Modules/SafeSpeak`.

### Что хранится (`Database/Migrations/2026_10_05_400001_create_safe_speak_tables.php`)
| Таблица | Колонки | Чего нет намеренно |
|---|---|---|
| `safe_speak_reports` | `access_code_hash (unique), category, subject, status, created_on (date), updated_on (date)` | нет `user_id`, `employee_id`, IP, user agent, **времени суток** (только дата), `created_at/updated_at` |
| `safe_speak_messages` | `report_id, author (reporter\|handler), handler_id?, body, created_on (date)` | у сообщений автора нет ничего, кроме слова `reporter`; `handler_id` — только у ответов обработчика (аудит), автору не показывается |

### Анонимная сторона — без сессии
`routes.public.php` подключается провайдером **вне групп `api`/`web`**: для `/api/safe-speak/public/*` не стартует
сессия (таблица `sessions` хранила бы IP и браузер), нет Sanctum, нет CSRF. Middleware `ForceJson` — ответы всегда
JSON (ошибка валидации не превращается в редирект с сессией). Контроллер берёт из запроса только форму и
**хэш-корзину клиента** `ClientBucket::of(ip, APP_KEY)` = HMAC-SHA256, 32 символа; сам IP дальше контроллера не идёт,
не пишется и не логируется. Пользователь (даже вошедший) не читается вообще.

| Метод и путь | Тело | Ответ |
|---|---|---|
| `POST /api/safe-speak/public/reports` | `{category, subject, body}` | 201 `{code, report}` (`Cache-Control: no-store`) |
| `POST /api/safe-speak/public/follow-up` | `{code}` | сообщение и ветка; неверный код — 404 `invalid_code` |
| `POST /api/safe-speak/public/reply` | `{code, body}` | 201; закрытое — 409 `report_closed` |

Код передаётся **только в теле**, никогда в URL (URL попадают в логи и историю браузера); `GET` на эти пути — 405.

### Код доступа (`Support/AccessCode`)
16 случайных символов Crockford base32 (80 бит, `random_int`), показ `XXXX-XXXX-XXXX-XXXX`. В БД — только
`HMAC-SHA256(APP_KEY, "safe-speak:" + нормализованный код)`: утёкшая таблица не превращается в коды, поиск — по
уникальному индексу. Нормализация: верхний регистр, без пробелов/дефисов, O→0, I/L→1.

### Лимиты (`Services/SafeSpeakService`, `Illuminate\Cache\RateLimiter`)
- **Отправка:** 5 сообщений в час на корзину клиента → 429 `too_many_attempts` + `Retry-After`.
- **Подбор кода:** 10 **неверных** кодов за 15 минут на корзину → 429 (и верный код тоже, пока окно не истекло).
  Удачные входы не считаются. Ключ лимитера — `safe-speak:code:<HMAC-корзина>`: в кэш (Postgres) попадает только хэш.
- При 80 битах энтропии и 40 попытках в час на адрес подбор бессмыслен даже с тысячами адресов.

### Обработчики
Колонка `users.safe_speak_handler` (миграция модуля Users). Gate `safe-speak-handle` = активный суперадмин/админ **и**
флаг. Маршруты `routes.php` (`auth:sanctum`): `GET /api/safe-speak/me` (`{handler}` для меню), `GET /reports?status=`,
`GET /reports/{id}`, `POST /reports/{id}/messages` (первый ответ: `new` → `in_review`), `PATCH /reports/{id}` `{status}`.

### Оговорки (что анонимность НЕ покрывает)
- Текст пишет человек: имя, должность или детали в тексте могут его выдать — форма предупреждает.
- Хостинг (Vercel) и сеть видят IP запроса на своём уровне (журналы платформы) — это вне приложения; приложение IP не
  хранит и не связывает с сообщением.
- Дата без времени и отсутствие сессии не дают сопоставить сообщение с входами пользователя в систему.

### Фронтенд
`frontend/src/app/features/safe-speak`: `report.page` (`/safe-speak`: форма, код показывается один раз и не
сохраняется в браузере; «У мене є код»), `inbox.page` (`/safe-speak/inbox`), `thread`, `safe-speak.service`.

## Как проверить
- `php artisan test --filter=SafeSpeak` — схема и строки БД не содержат ни IP, ни user agent, ни id/имени/почты
  отправителя (в т.ч. вошедшего), нет записи в `sessions`; код хранится только HMAC; лимит неверных кодов и отправок
  (ключи кэша без IP); доступ обработчика — только админ + флаг; флаг в админке пользователей.
- Вручную: отправить сообщение, сохранить код, открыть по коду; обработчиком ответить — ответ виден по коду.

# Каналы привлечения кандидатов (ТЗ 3, часть модуля Recruiting)

> Не путать с [channels.md](channels.md) — там мессенджеры и телефония (каналы **общения**). Здесь — каналы
> **привлечения**: откуда кандидат пришёл (job-сайт, реклама, рекомендация…).

## Что это и зачем
Публикации вакансий стоят денег, а какой канал реально приводит до найма — было непонятно. Теперь у каждого кандидата
два отдельных факта: **канал** (откуда пришёл — Work.ua, Meta Ads, рекомендация…) и **способ добавления** (как попал в
SinHRM — вручную, импорт, почта, расширение, Google Sheets, вебхук). Канал ставится **автоматически** по UTM-меткам
ссылки или по источнику, либо рекрутер выбирает его сам. Отчёт показывает по каналам: сколько кандидатов, сколько
дошли до отбора, сколько наняты, конверсию и (если внесены расходы) **цену найма**. В карточке вакансии — блок «Джерела
відгуків».

## Как пользоваться
- **Адміністрування → Канали залучення** (`/admin/acquisition-channels`, админы): канал = название + **технічна назва**
  (код, по нему узнаются импорт и ссылки) + тип (job-сайт, реклама, рекомендация, соцсети, сайт, событие, агентство,
  другое) + «Активний». У канала — **правила UTM** (`utm_source` / `utm_medium` / `utm_campaign`, пустое = любое,
  приоритет) и **расходы за периоды**. Блок «Перевірити UTM» показывает, какой канал получится.
- **Кандидат**: в форме — «Канал залучення» (по умолчанию «Автоматично»); в карточке — чипы «канал» и «як додано»;
  в списке — фильтр по каналу.
- **Вакансия** (доска): раскрывающийся блок «Джерела відгуків» — канал × способ, количество и доля.
- **Каталог отчётов → «Ефективність каналів залучення»**.

### Определение канала (`Services/AcquisitionChannelService::resolve`, `Support/UtmMatcher`)
Порядок: 1) явный `channel_id` (должен быть активным, иначе 422 `channel_inactive`); 2) правило UTM — подходит, если
**все** заполненные поля правила равны меткам кандидата (без учёта регистра и пробелов; ключи `source` и `utm_source`
равнозначны); среди подходящих побеждает **более точное** (больше заполненных полей), затем меньший `priority`, затем
старшее; правило без полей не допускается (422 `empty_utm_rule`); 3) активный канал с кодом, равным старому источнику
(`work_ua`, `linkedin`, …); 4) нет канала. Правка UTM у существующего кандидата канал не меняет — только явный `channel_id`.

| Путь создания | `added_via` | Канал |
|---|---|---|
| форма кандидата, «Вхідні» → «Створити кандидата» | `manual` | явный / UTM / источник |
| почтовый агент (отклик с job-сайта) | `mail` | UTM / источник письма (`work_ua`, `robota_ua`, `djinni`) |
| импорт из Google Sheets | `sheets` | колонки UTM / колонка «Джерело» |
| расширение браузера | `extension` | сайт профиля (`linkedin`, `work_ua`, `djinni`, `dou`) |
| прочий машинный импорт (`createOrMatch`) | `import` | UTM / источник |
| вебхук лид-формы | `webhook` | значение зарезервировано — такого входа пока нет |

### Миграция источника в каналы (`…200002_seed_channels_from_sources.php`, повторяемая)
Каналы с кодами старых источников `work_ua, robota_ua, djinni, dou, linkedin, telegram, meta_ads, site, referral,
other` + `grc_ua, instagram, google_ads, job_fair, agency`; правила UTM для очевидных меток (`work.ua`, `djinni`,
`facebook`+`paid` → Meta Ads, `google`+`cpc` → Google Ads…). Существующие кандидаты: `channel_id` по коду = `source`;
`manual`/`inbox` → `added_via = manual`, `import` → `import`, есть ссылка профиля расширения → `extension`;
остальное — `null` («неизвестно»). `manual`, `import`, `inbox` — это способ, а не канал, поэтому канала у них нет.

### Отчёт `channel_effectiveness` (`ReportService::channels`, `Support/ChannelMath`)
Кандидаты, **созданные в периоде**, по каналу (в филиалах пользователя, как отчёт источников): `candidates`,
`applications`, `advanced` (заявки, дошедшие до этапа типа «отбор» или «найм»), `hired` (кандидаты с нанятой заявкой),
`conversion_pct = hired ÷ candidates × 100`. **Расходы** — строки, пересекающие период, пропорционально дням:
`amount × дни пересечения ÷ дни периода строки`; `cost_per_hire = cost ÷ hired` (нет наймов — пусто). Расходы и цена
найма видны только управляющим справочником (админам): суммы общие по компании, а счётчики — в области пользователя.

### Отклонения от ТЗ 3
- «Автоматический сбор откликов на вакансии, опубликованные через внешнюю систему» — публикации на job-сайтах и интеграции с внешними HR-системами нет; отклики
  приходят почтовым агентом, импортом и расширением (им ставится канал и способ).
- Отчёт «канал → этап → закрытие вакансии» сведён в один отчёт: «дошли до отбора» и «наняты» по каналу.
- Вебхуков лид-форм нет — значение `webhook` зарезервировано.
- Hurma даёт 28 каналов «из коробки»; у нас 15 общих, остальные добавляются в справочнике.

## Как проверить
`php artisan test --filter=AcquisitionChannels` — права справочника, приоритет UTM, явный канал, способ добавления на
машинных путях, миграция источника в каналы (повторный запуск), математика отчёта (пропорция расходов, конверсия,
цена найма, скрытие расходов не админу), блок вакансии; `ChannelSupportTest`.

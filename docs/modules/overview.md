# Модуль Overview — главная страница (дашборд)

## Что это и зачем
Первый экран после входа отвечает на вопрос «что мне сделать сегодня»: сколько кандидатов в работе, кто «завис» без
контакта, что лежит неразобранным во «Вхідних», какие задачи на сегодня, как выглядит воронка и сколько было касаний за
неделю. Всё — в пределах филиалов пользователя. Спокойные карточки без графиков-«ёлок»: числа и полоски.

Прежняя стартовая страница «Стан системи» (проверка API и базы) переехала на `/status` — пункт меню для суперадмина и админа.

## Как пользоваться
Порядок блоков (с 2026-10-02, макет C «Маршрут»): шапка с датой и кнопками «Мої задачі · N», «+ Кандидат», «Оновити» →
предупреждения → **«Маршрут дня»** → четыре счётчика → сетка «воронка | без контакту», «мої задачі | касання + відсутні
сьогодні» → остальные карточки (настроение, согласования, заявки, мой тиждень, табели). Подробнее — «Интерфейс (2026-10-02,
раскладка…)» ниже; описание отдельных карточек ниже остаётся в силе.
Меню → «Огляд» (или логотип). Первая карточка — **«Як ваш настрій сьогодні?»** (пять смайликов и комментарий;
только если пользователь связан с сотрудником и сегодня день опроса; после ответа — сегодняшний смайлик) — компонент
`MoodCheckinWidget` модуля Pulse ([pulse.md](pulse.md)), данные — `GET /api/pulse/mood/today`, не `/api/dashboard`. Карточки **«Відсутні сьогодні»** (всегда) и **«Чекають мого погодження»** (если есть что решать) —
из модуля отсутствий ([timeoff.md](timeoff.md)), ссылки ведут в календарь команды и в «Погодження». Карточки
**«Заявки на підбір чекають мого рішення»** ([hiring-requests.md](hiring-requests.md)), **«Мій тиждень»** и **«Табелі
чекають мого погодження»** ([time.md](time.md)) — если есть что показать. Сверху четыре счётчика — клик ведёт в раздел:
«активних кандидатів» → Кандидати, «без контакту 3+ дні» → Кандидати, «нерозібраних у Вхідних» → Вхідні,
«нових сьогодні» → Вакансії. Ненулевые «зависшие» и «Вхідні» подсвечены.
Ниже: **Мої задачі на сьогодні** (включая просроченные; галочка закрывает задачу — [scripts.md](scripts.md)),
**Без контакту 3+ дні** (10 самых давних, клик — карточка кандидата), **Воронка активних кандидатів** (по этапам всех
вакансий) и **Касання за 7 днів** по каналам. Кнопка «Оновити» перечитывает данные.

### «Сегодня» — день пользователя, не UTC (2026-10-02)
База и API хранят время в UTC, а интерфейс показывает местное (Киев). Если резать «сегодня» по UTC, с 00:00 до 03:00
(летом; зимой до 02:00) шапка показывает новый день, а маршрут и задачи — ещё вчерашний, и метка «зараз» не рисуется.
Поэтому границы дня — по часовому поясу пользователя: `Core\Support\UserTime` ([core.md](core.md)). Настройки пояса у
пользователя или компании в проекте нет — один пояс для всех, `config('app.user_timezone')` (env `APP_USER_TIMEZONE`,
по умолчанию `Europe/Kyiv`; переход на летнее время учитывает сам пояс). По нему считаются `counts.new_today`,
`my_tasks` (`due=today` и просрочка — [scripts.md](scripts.md)) и `day_route`: `date` — дата в этом поясе, все `at`/`end` — со
смещением пояса (`+02:00` зимой, `+03:00` летом), `timezone` — его имя. Фронт (`routeScale`/`routeStops`, `wallClock` в
`overview.model.ts`) читает часы линии, отметку «зараз» и дату в шапке именно в `day_route.timezone`, а не в поясе браузера,
поэтому шапка и маршрут всегда показывают один день. Остальные окна (90 дней воронки, 7 дней касаний, «зависшие») — от
текущего момента, пояс на них не влияет.

### Новые показатели (2026-10-02): источник и формула
Только реальные данные из БД; если источника нет или выборка мала — блок или подпись скрыты, чисел-заглушек нет.

| Показатель | Источник | Формула и порог |
|---|---|---|
| **Маршрут дня — интервью** | касания канала `meeting` с `meta.start` (их создаёт «Запланувати зустріч» в карточке кандидата, модуль GoogleWorkspace; в `meta.start/end` — время встречи, а не время записи) | Встреча, у которой `meta.start` попадает в текущий день пользователя `[00:00, 23:59:59]` в `app.user_timezone` (тот же день, что «Мої задачі на сьогодні» и дата в шапке). Только «мои»: автор касания — пользователь **или** пользователь назначен интервьюером заявки (`application_interviewers`). Плюс кандидат должен быть виден пользователю (`CandidateRepository::isVisible`, те же правила, что в «Кандидатах»). Админ видит всё в подборе, но маршрут — личный. SQL отбирает грубое окно ±1 день по тексту `meta->start` (`meta->start` билдера Laravel = `json_unquote(json_extract())` на MySQL), точное окно — в PHP после разбора даты; битые значения пропускаются. |
| **Маршрут дня — задачи** | `tasks` через `Scripts\Services\TaskService` (`mine`, `due=today`) | Мои открытые задачи с `due_at` внутри текущего дня пользователя (время в ответе — в его поясе). Просроченные на линию не попадают (остаются в «Мої задачі на сьогодні»). |
| **Подпись «N інтерв'ю · M задач»** | `day_route.interviews`, `day_route.tasks` | Количество элементов выше. |
| **«Найвужче місце» A → B** | `stage_changes` + `pipeline_stages`, заявки в филиалах пользователя (как воронка: `RecruitingScope`, без чужих филиалов) | Когорта: заявки, чей маршрут начался (первый `stage_changes.at`) за последние **90 дней**. Для каждой — самая дальняя достигнутая позиция среди этапов, кроме `closed`. Пары соседних этапов маршрута (этапы `closed` пропускаются). Конверсия A → B = дошли до B / «решённые» на A (дошли до B **или** заявка закрыта/нанята). Заявки, которые ещё активны на A, не считаются — их исход неизвестен. Пара учитывается при **≥ 10** решённых; воронки с одинаковыми названиями этапов суммируются. Показывается пара с наименьшей конверсией (при равенстве — более ранняя): процент и выборка — «38% (5 з 13) за 90 днів» (`passed` з `decided`). Нет ни одной пары с выборкой ≥ 10 → `bottleneck: null`, подписи нет. |
| **«Середній шлях до оферу»** | `stage_changes` + `pipeline_stages.kind = hire` | Заявки в филиалах пользователя, впервые вошедшие в этап вида `hire` (в стандартной воронке — «Офер» и дальше) за последние **90 дней**. Дни = от начала маршрута (первый `stage_changes.at` = отклик; учитывает дату отклика при импорте) до этого первого входа; среднее, округлённое до целых. Меньше **3** наблюдений → `offer_path: null`, подписи нет. |
| **Подсказка «мало данных»** (`overview.insights.notEnough`) | `min_sample`, `min_offer_observations`, `period_days` | Только когда нет обеих подписей. Пороги у подписей разные и названы оба: «Найвужче місце з’явиться, коли на етапі буде від 10 рішень, а шлях до оферу — від 3 оферів (за 90 днів)». |
| **Касання за 7 днів (полоса)** | `touches.by_channel` (уже был) | Стековая полоса: ширина сегмента = доля канала в сумме касаний за 7 дней; легенда — канал и число. |

Не реализовано из макета (нет реального источника): дельты и мини-тренды у счётчиков («+5 за тиждень»), конверсия
у каждой станции воронки — не входили в задачу; «Відсутні цього тижня» — оставлено «Відсутні сьогодні» (данные `timeoff.out_today`).

Ограничение по филиалам — `Recruiting\Services\RecruitingScope` (superadmin/admin видят всё, остальные — вакансии своих
филиалов; пользователь без филиалов видит нули).

Фронтенд — `frontend/src/app/features/overview`: `dashboard.page.*` (маршрут `''`; баннеры `warnings` со ссылкой — строки
`overview.warnings.<code>`), `overview.store.ts` (плитки, ширины
полосок), `overview.service.ts`, `overview.model.ts` (`statTiles` — куда ведёт каждый счётчик). Виджет задач —
`features/scripts/tasks/tasks-widget.ts`. Строки — `overview.*` в `public/i18n/{uk,ru,en}.json`.

**Интерфейс (2026-09-26):** Блок «Дотики за каналами» — иконки каналов Font Awesome в цветах бренда (`app-channel-icon`, [core.md](core.md)).

**Интерфейс (2026-10-02, рестайл C «Маршрут»):** счётчики — плитки с цветной «шпалой» сверху и моноширинным числом
(ненулевые «без контакту» и «Вхідні» — цвет предупреждения); **воронка — линия метро**: вертикальная линия через станции,
станция и линия — в цвете типа этапа (`stage_kind` → `--app-stage-*`), диаметр станции растёт с долей этапа от самого
большого (`--share` = ширина полоски / 100), рядом — та же полоска на «треке» и число. Таблица воронки осталась таблицей
(те же строки и заголовки строк — для скринридера и ui-parity). Полоски воронки прорисовываются слева за 600 мс — единственная
анимация «трасса» на странице; с `prefers-reduced-motion` всё статично. Тест — `overview.spec.ts` («route look»).

**Интерфейс (2026-10-02, раскладка по макету C «Маршрут»):** шапка — крошка «Огляд — <сегодняшняя дата>», приветствие,
кнопки «Мої задачі · N» (`/tasks`, N = `my_tasks.total`), «+ Кандидат» (диалог создания кандидата; только если можно
писать в подбор — `canWriteRecruiting` и модуль `recruiting` включён) и «Оновити». Ниже баннеры `warnings`, затем
**«Маршрут дня»** на всю ширину: линия 9:00–19:00 (расширяется до самого раннего/позднего события), станции событий
(интервью — бирюзовые, задачи — синие), отметка «зараз» и пройденная часть линии; под линией — список событий
(время, тип, кандидат/название; интервью ведут в карточку кандидата). Пусто — `app-empty`. На телефоне линия не
прокручивается (горизонтальной прокрутки нет ни у карточки, ни у страницы): она сжимается по ширине экрана, а каждая
вторая подпись часов скрыта (`.hr.minor`), чтобы подписи не налезали друг на друга; список событий — в одну колонку. Потом четыре счётчика и сетка 7+5: воронка (с подписями
«Найвужче місце», «Середній шлях до оферу», если данных достаточно) | «Без контакту N+ днів»; «Мої задачі на сьогодні» |
«Касання за 7 днів» (стековая полоса + легенда) и «Відсутні сьогодні». Блоки не из макета (настроение, мои согласования
отпусков, заявки на подбор, мой тиждень, табели) — ниже основной сетки. Анимации: одна «трасса» (пройденная часть
линии маршрута дня прорисовывается за 600 мс; полоски воронки больше не анимируются) и одна «поп» (карточки сетки
появляются за 280 мс); с `prefers-reduced-motion` — статично.
Внутренний отступ карточек (в т.ч. «Маршрут дня», у которой свои изолированные стили компонента) — общий токен `--app-card-pad` из `styles.scss` (1.1rem 1.25rem; 1rem на телефоне): отдельная копия отступа в компоненте не нужна — стили страницы до дочернего компонента не доходят. Тест — `overview.spec.ts` («card padding»).

### Общие примитивы фронта
Общий код фронта лежит в `frontend/src/app/core` ([core.md](core.md)); фича его только вызывает.
- HTTP-сервис фичи снимает обёртку ответа `{ data }` общим оператором `unwrapData()` (`core/api/unwrap-data.ts`, тип `DataEnvelope<T>` из `core/api/api.model.ts`) вместо своего `map((r) => r.data)`; параметры запроса без пустых значений — `toParams` из `core/api/http-params.ts`, страница списка — `Paged<T>` оттуда же. Контракт API не менялся.

### Зависимости через контракты (2026-10-08)
- `DashboardService` читает задачи пользователя через контракт Scripts `TaskReader::list()` (не через класс `TaskService`).
- `DashboardService` берёт область видимости через контракт Recruiting `RecruitingAccess`, порог «застоя» — из `ApplicationRepository::STALE_DAYS` (вместо `StalenessService::DEFAULT_DAYS`). Тест — `tests/Unit/Overview/DashboardContractsTest.php` (главная собирается из ответов контрактов, без БД).

00:15 завтра — нет, задача в 23:30 по Киеву на линии, `my_tasks.total`/`overdue` по киевскому дню); `day_route` (только встречи сегодня, где я автор или интервьюер, и только
видимые кандидаты; просроченные задачи не на линии; интервьюер-сотрудник видит своё интервью; админ — пустой личный маршрут)
и `funnel_insights` (узкое место 30% и путь 15 дн. по истории этапов; чужой филиал и viewer без филиалов — `null`; вне окна
90 дней и при малой выборке — `null`). `tests/Unit/Overview/FunnelInsightsServiceTest` — формулы и пороги.
Фронт: `overview.spec.ts` (в т. ч. линия в `day_route.timezone`: 00:45 по Киеву = 21:45 UTC — «зараз» есть; подписи
«N% (passed з decided)» и подсказка с обоими порогами; дата в шапке — в поясе маршрута).
Вручную: войти → «Огляд» → счётчики совпадают с «Кандидати»/«Вхідні», клик по зависшему открывает карточку.

## Доступ к модулю

### Предупреждение о переподключении Google

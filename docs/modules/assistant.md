# Модуль Assistant (помощник «Стік»)

## Что это и зачем
«Стік» — нарисованный человечек-помощник, который живёт поверх интерфейса: иногда сам выходит из-за края экрана
(выглядывает, вылезает, выпрыгивает, падает сверху) или из нарисованной двери, люка, портала, реагирует на курсор и на то, что происходит, и с ним можно
поговорить. Он объясняет «как сделать», читает разрешённые идентификаторы и счётчики и предлагает действия —
**строго с текущими правами пользователя и дополнительной границей данных для AI**. Встроенный чат изменяет
данные только после клика «Виконати»; внешний MCP-клиент управляет подтверждением в своём интерфейсе.

Тот же набор инструментов доступен внешним AI-клиентам (Claude Desktop, Claude Code, любой MCP-клиент) через
**MCP-сервер** `POST /api/mcp` — по личному токену пользователя.

## Как пользоваться
- На узком экране (менее 768 px) чат открывается кнопкой Стіка в верхней панели. Фигура и её круг не перекрывают строки и карточки, цикл анимации остановлен; при возврате на широкий экран применяется сохранённая настройка анимации.
- Нажмите на Стіка (или на маленький круг с глазами в правом нижнем углу, если он выключен) — откроется чат.
  Пишите как человеку: «Скільки кандидатів у списку?», «Відкрий /people/42», «Як змінити етап кандидата?».
  Ассистент не узнаёт сотрудника по имени из API и не читает зарплату: выберите запись в интерфейсе и укажите её ID.
  Для изменений Стік показывает карточку «що саме зміниться» — выполняется только после «Виконати».
- Меню чата: «Нова розмова», вкл/выкл Стіка (выключенный — круг с глазами, которые следят за курсором; сам не
  выходит), «Підключити до Claude / MCP».
- **Подключение к Claude.** Меню чата → «Підключити до Claude / MCP» → «Створити токен» (показывается один раз) →
  скопировать готовую команду, например
  `claude mcp add --transport http sinhrm https://<домен>/api/mcp --header "Authorization: Bearer <токен>"`.
  Токен: 90 дней, один на пользователя (новый отзывает старый), «Відкликати» — сразу.
- Если ИИ выключен в админке (глобальный выключатель, интеграция AI Broker или переключатель «ШІ: помічник Стік»),
  Стік продолжает жить и шутить, а в чате объясняет, почему не может ответить.

## Как устроено

### Инструменты (один набор для чата и MCP)
`Contracts/AssistantTool` — имя, описание, JSON-схема аргументов, где выполняется в чате (`Enums/ToolRunner`:
`Server` | `Client`), меняет ли данные, доступен ли по MCP, `run(User, args)`. Классы тегируются
`AssistantServiceProvider::TOOLS_TAG` — **любой модуль может добавить свой инструмент**. `Support/ToolRegistry`
отдаёт их отсортированными (побайтно стабильный список — часть кешируемого префикса промпта).

| Инструмент | Чат | MCP | Что делает |
|---|---|---|---|
| `find_endpoints` | сервер | да | поиск по живой карте API (`Support/EndpointCatalog`) |
| `api_get` | браузер | да (read-only) | GET; в автоматическую историю AI и MCP попадает только серверная проекция из матрицы ниже |
| `api_write` | браузер, **после подтверждения** | да (destructive) | POST/PUT/PATCH/DELETE; `summary` — текст карточки подтверждения |
| `open_page` | браузер | нет | открыть страницу SPA |

**Карта API** (`EndpointCatalog`) строится из таблицы маршрутов Laravel при вызове, а не из списка в коде: каждый
новый эндпоинт появляется в метаданных карты; это не разрешение передать его данные AI. В неё попадают только маршруты `api/*` с `auth:sanctum` из модулей,
которые пользователь может открыть (`ModuleAccess`), без закрытых префиксов. Для каждого: метод, путь, модуль, первая
строка docblock экшена контроллера и правила его FormRequest (поля тела; для GET — параметры запроса).

**Закрытые пути** (`Support/ApiPath`, зеркало во фронте `assistant-tools.ts`): `ops`, `mcp`, `assistant`, `auth/logout`,
`sanctum`, `clipper`, `public`, `me/extension-token`, `webhooks`; запрещены `..`, `//`, абсолютные URL. Всё остальное
всё равно проходит проверку доступа к модулю, гейты и политики — список только убирает то, что ИИ трогать не должен.

### Чат (`/api/assistant/*`, сессия)
Историю для отображения хранит SPA; сервер не хранит переписку, но связывает ответ с отпечатком доступа в кеше.
Один `POST /api/assistant/turn` = **ровно один** вызов
модели через `AiService` (ворота AI, дневные лимиты, запись в `ai_requests`, без логирования промптов), поэтому каждый
запрос укладывается в 60 с Vercel (ожидание модели ≤ 25 с).
1. SPA шлёт `{messages, page: {path, title}}` (формат сообщений OpenAI: user / assistant с `tool_calls` / tool).
   По умолчанию (`native_tools = off`) инструменты уходят модели не нативно, а через эмуляцию строгим JSON
   ([ai.md](ai.md), «Эмуляция tools») — ход может обслужить любой живой провайдер брокера; для чата разницы нет.
2. `Services/AssistantChatService` сначала проверяет доступность AI, затем `AssistantHistory` пересобирает доверенную
   историю, собирает промпт (`Ai/AssistantPrompt`) и вызывает `AiService::run`
   (цель `AiPurpose::AssistantChat`, subject `assistant_user` + id пользователя).
3. Ответ модели проверяет `Ai/AssistantChatHandler` (реализует `AiConversationHandler`): только известные инструменты,
   аргументы — JSON-объект, ≤ 8 вызовов, не пустой ответ; иначе один повтор, затем `ai_invalid_output`.
4. Вызовы `Server` выполняются сразу → `server_results`; вызовы `Client` → `client_calls`. SPA выполняет их своей
   сессией (запись — только после клика), дописывает результаты и шлёт следующий ход; текст без вызовов — финальный
   ответ. Лимит во фронте — 8 ходов на одно сообщение.
5. Не успел за 25 с → `{state: pending, request_id}`; SPA опрашивает `GET /api/assistant/turns/{id}` (только владелец,
   чужой — 404). Готовый ход держится в кеше 15 мин (`assistant.turn.<id>`), так что его заберут и после `ai.poll`.

**Граница automatic API/tool → AI** (`AssistantDataPolicy`, `AssistantHistory`, `InternalApi`): права SPA и
подтверждение записи не меняются. Браузер по-прежнему выполняет `client_calls` своей сессией, но его ответы не
являются доказательством для модели. MCP GET использует ту же серверную матрицу. Неизвестный или чувствительный
GET получает `403 forbidden_path` **до** обращения к маршруту, даже для superadmin.

| Разрешённый GET | Поля после проекции |
|---|---|
| `auth/me` | только `id` |
| `people`, `people/{numeric id}`, `me/employee`, `people/search`, `people/lookup` | `id`, `user_id`, `candidate_id`, `branch_id`, `department_id`, `position_id`, `manager_id`; только `id` внутри `branch`, `department`, `position`, `manager` |
| `candidates`, `candidates/{numeric id}` | `id`, `city_id`, `channel_id`, `owner_id`; только `id` внутри `city`, `channel`, `owner`; `applications` по отдельной схеме ниже |
| `vacancies`, `vacancies/{numeric id}` | `id`, `branch_id`, `department_id`, `position_id`, `recruiter_id`, `hiring_manager_id`, `pipeline_id`, `category_id`, `city_id`; только `id` внутри справочных объектов и `stages` |
| `tasks`, `tasks/{numeric id}` | `id`, `assignee_id`, `application_id`; только `id` внутри `employee`, `candidate`, `vacancy` |
| `pipelines` | `id`, только `id` в `stages` |

В `candidates.applications` разрешены `id`, `candidate_id`, `vacancy_id`, `stage_id`, `reject_reason_id`, только `id`
в `candidate`, `vacancy`, `stage`, списках `stages` и `interviewers`. Для разрешённых ресурсов сохраняются только
целые неотрицательные счётчики `meta.current_page`, `last_page`, `per_page`, `from`, `to`, `total`. Идентификаторы
должны быть положительными PHP integer; строки с цифрами, bool, float, null и вложенные значения не проходят.
Это **псевдонимные**, а не анонимные данные: ID и связи могут относиться к человеку.

Проекция знает точные позиции объектов; совпадение имени `id` в `custom_fields` ничего не разрешает. Нет имён,
контактов, адресов, custom fields, компенсации, дат, статусов/enum, свободного текста, URL и ссылок пагинации.
Другие чтения закрыты: compensation, history, документы, timeoff, perform, pulse, SafeSpeak, users, integrations,
privacy и org-chart. Реальный API после whitelist проверяет текущую роль, ModuleAccess, branch scope и контекстные
назначения; People directory намеренно доступен всем активным пользователям компании. `tenant_id` в модели нет:
эта граница не создаёт tenant isolation и не меняет доступ каталога People.

`AssistantHistory` сохраняет прямой текст пользователя, но удаляет весь клиентский текст ассистента. Только последний
раунд инструментов, если история заканчивается результатом tool, повторно читает GET или заново ищет метаданные
`find_endpoints` как **текущий аутентифицированный User**, максимум 8 вызовов. Старые результаты заменяются
`older_tool_result`; если последний автор — user, старые GET не повторяются. Клиентские ID используются только для
локального сопоставления, модели выдаются последовательные `history_N`. Неизвестные, отсутствующие, дублированные
или несопоставленные вызовы/результаты отбрасываются. Аргументы для модели содержат лишь известный путь с числовым
ID, метод записи или проверенный ключ модуля; query, body, summary и произвольные сегменты не отправляются.
Повторное чтение использует исходные аргументы локально, поэтому фильтры работают, но их значения не уходят модели.

Записи никогда не повторяются из истории. Это не общая гарантия exactly-once: если модель предлагает такую же
запись новым вызовом, интерфейс снова требует отдельное подтверждение; idempotency key для таких действий нет.
Их браузерские результаты получают `unverified` + безопасное
`write_result_omitted`/`write_declined`; `open_page` — такое же неподтверждённое общее подтверждение навигации.
Прямой `InternalApi` write сохраняет существующее действие/права, но возвращает только HTTP status; ошибки GET/write
содержат status и фиксированный код, без текста ошибки, validation values и сырого тела. Проекция выполняется
**до** ограничения 12 000 символов в InternalApi и 4000 для свежего результата истории. `find_endpoints` сохраняет
не более 8 записей метаданных; definitions и system побайтно стабильны между ходами.

Цена приватности: модель не помнит прежние объяснения ассистента, не распознаёт людей по имени из API и не отвечает
на вопросы о зарплатах/других закрытых данных. Пользователь может открыть нужную страницу и спросить о работе UI.
**Прямой пользовательский текст намеренно передаётся AI**, включая вписанные пользователем персональные сведения;
это не универсальная редакция или обещание, что никакие PII никогда не попадут AI. История UI остаётся полной.
`TurnRequest` проверяет форму и размер (≤ 60 сообщений, ≤ 14 000 символов, ≤ 8 tool calls на сообщение), затем
серверная граница отдельно проверяет происхождение результатов. Выключенный AI не вызывает повторных API-чтений.
Если остались только несопоставленные tool results без доверенного запроса, ход завершается до отправки модели.

**Свежесть доступа при ответе.** Рядом с `assistant.turn.<id>` хранится SHA256 `assistant.scope.<id>` на 900 секунд:
ID/status пользователя, effective роли и permissions свежего User, активные назначенные branch IDs из
DictionaryRepository, известные hiring-manager vacancy IDs/interviewer application IDs из HiringTeamRepository
и `ModuleAccess.allowedKeys`. Отдельный свежий снимок ModuleSettingsRepository выявляет изменение конфигурации
модулей другим запросом, даже если текущий ModuleAccess ещё держит старое значение в памяти.
Загруженные до ожидания User/relations не служат доказательством текущих прав.
Выбранная act-as роль сохраняется; если её больше нет среди назначенных ролей, запрос закрывается без возврата
к более широкой роли. Неактивный или удалённый actor также не получает результат.
Проверка выполняется до сборки истории и после неё, после ожидания `AiService::run` и, при poll, до и после
provider refresh, перед выдачей кеша и выполнением server tools. Изменение доступа, отсутствие или истечение
отпечатка дают `ai_context_changed`; пользователь может отправить новый запрос.
Это ограниченная проверка свежести, не атомарный снимок всех ACL. Произвольные изменения владельца записи,
task assignments и текста данных не входят в отпечаток; определения permissions имеют собственный framework cache.
Уже отправленные провайдеру данные и уже показанный UI-текст не отзываются. Смена effective роли того же
пользователя не очищает transcript или открытую карточку подтверждения; последующий HTTP write проверяет права API заново.

Доступ к кандидату сейчас проверяется как к целой записи: его API может вернуть applications нескольких веток,
включая вложенный vacancy ID, чей отдельный endpoint недоступен этому actor. Проекция сохраняет разрешённые схемой
ID; она не добавляет отдельную ACL к каждой вложенной ссылке. Для строгой изоляции таких связей нужен отдельный
контракт доступа и исправление, это не доказательство tenant isolation.

Фронтенд переводит `ai_context_changed` на uk/ru/en и предлагает повторить запрос. Стартовые подсказки и реплики
маскота на трёх языках предлагают навигацию и доступные счётчики; они не обещают чтение имён, отпусков, встреч,
статей или отчётов через AI. Regression `assistant-context.pw.ts`
проверяет pending → изменение контекста → локализованную ошибку в четырёх проектах и трёх языках; обычные viewport
PNG пустого чата/ошибки/MCP privacy warning с provenance, геометрия панели, scoped axe, строгий запрет непредусмотренных API-вызовов и
записей. Эти снимки и полный backend набор требуют CI; локальный сервер для проверки не поднимается.
Панель использует `border-box`: её рамка входит в ширину мобильной шторки и не выходит за viewport на 2 px.

### Диктовка голосом
Кнопка-микрофон в чате записывает голос (MediaRecorder, ≤ 120 с, ≤ 4 МБ — лимит тела запроса Vercel 4,5 МБ) и шлёт в
`POST /api/assistant/transcribe`. `Services/AssistantVoiceService` → `AiService::transcribe` (цель
`AiPurpose::AssistantVoice`, **тот же выключатель `ai_assistant_chat`**, общие дневные лимиты, строка в `ai_requests` с
`capability = transcription`) → брокер `POST /v1/transcribe/jobs` (Whisper: local → groq → gemini → openai). Ответ
брокера ждём ≤ 25 с; медленный (запасной локальный Whisper — до ~2,5 мин) → `pending`, SPA опрашивает
`GET /api/assistant/transcriptions/{id}` (только владелец, 15 мин в кеше — `Ai/AssistantVoiceHandler`). Текст
**вставляется в поле ввода** — пользователь правит и отправляет сам; тишина → `empty_transcript`. Аудио SinHRM не
хранит (передаётся один раз под нейтральным именем `voice.<ext>`; брокер удаляет его по завершении задачи).
Браузер даёт доступ к микрофону, только если заголовок SPA `Permissions-Policy` его разрешает: в `frontend/vercel.json`
стоит `microphone=(self)` (до 02.10.2026 было `microphone=()`, и диктовка в проде не работала) —
[architecture/observability.md](../architecture/observability.md).
Лимит — 10 записей/мин на пользователя. У ключа проекта в брокере должна быть область `transcription`, иначе ответ
`ai_provider_http_403` — **на живом брокере не проверялось**.

### Шутки после падения (`GET /api/assistant/quips`)
`Services/AssistantQuipService`: одна пачка из ≤ 10 шуток на ситуацию (`fall` / `thrown` / `slip`) и язык (`uk` / `ru` /
`en`), общая для всех пользователей, в кеше 6 ч — один запрос к ИИ на пару за 6 ч, а не на каждое падение. Цель
`AiPurpose::AssistantQuips` (выключатель общий с `ai_assistant_chat`), промпт `assistant_quips.v1`
(`Ai/QuipsPrompt`, текст — [ai.md](ai.md)), без персональных данных. Пачку генерирует один запрос за раз (замок в
кеше); медленная генерация → `{jokes: [], source: "none"}` (SPA говорит встроенные фразы), id запроса хранится в
замке, и **следующий вызов дочитывает тот же запрос** из брокера (прод 29.09: полоса не успела за 20 с, а `ai.poll`
ходит раз в 30 мин); неудачная не повторяется 10 мин. SPA переспрашивает пустую пачку не чаще раза в минуту, до 4 раз
за сессию; пачку, дозавершённую `ai.poll`, кладёт в кеш `Ai/QuipsHandler`. Шутки длиннее 120 символов и
дубли отбрасываются. 30 запросов/мин.

### Промпт `assistant.v3` и кеширование
Текст — `AssistantPrompt::SYSTEM` (ROLE → TASK → RULES → APP MAP → OUTPUT, английский; ответ — на языке пользователя).
Смена текста = новая версия `VERSION`. В `system` и описаниях инструментов нет дат, имён, id и данных страницы;
контекст хода (`roles; today <дата>; current page <известный путь>`) дописывается в начало **последнего** сообщения
пользователя. Имя, заголовок страницы, query и произвольные path segments исключены. Стабильный префикс (system +
каталог инструментов) не содержит данных хода; кеширование зависит от модели полосы `chat:fast` брокера.
Бюджет ответа хода — `AiPrompt::CONVERSATION_MAX_TOKENS` (3000): рассуждающие модели бесплатных полос (gpt-oss) тратят
часть `max_tokens` на скрытые рассуждения. Причина отказа хода (`invalid_reason`, `finish_reason`) пишется в
`ai_requests.meta` и отдаётся в ответе хода как `detail` — только коды, без текста ответа.
**Проверить кеш по `ai_requests.tokens_cached` сейчас нельзя:** брокер сохраняет `cache_read_tokens` в метаданных
задачи (`job_queue.py`), но не отдаёт это поле в ответе `GET /v1/jobs/{id}` (`DeepJobResponse`) — у всех целей SinHRM
там 0 независимо от реального кеша. Нужна правка в брокере. На живом брокере ход с tools не проверялся (нет ключа
в среде разработки).

### MCP-сервер (`POST /api/mcp`)
`Mcp/SinhrmMcpServer` на официальном пакете `laravel/mcp` (MIT, Streamable HTTP, JSON-RPC). Инструменты — те же
`AssistantTool` с `overMcp() = true`, обёрнутые `Mcp/BridgedTool` (та же схема, подсказки `readOnlyHint` /
`destructiveHint`). Вызов выполняет `Services/InternalApi`: подзапрос проходит через роутер со **всеми** middleware
маршрута (доступ к модулю, гейты, политики, валидация) от имени владельца токена; GET дополнительно ограничен матрицей
и проецируется до обрезки 12 000 символов, write отдаёт status/фиксированный код ошибки.
Middleware: `auth:sanctum`, `EnsureUserIsActive`, доступ к модулю `assistant`, `throttle` 60/мин на токен.
В OpenAPI (`/api/docs`) маршрут не попадает — это не REST.

### Токены
`Services/McpTokenService`: имя `mcp`, ability `mcp`, 90 дней, один на пользователя — поверх общих
`Auth/Services/PersonalTokens` (те же, что у токена расширения, [auth.md](auth.md)). Где токен принимается, решает
`Auth/Support/TokenScopes`: модуль регистрирует `api/mcp → mcp`, поэтому MCP-токен получает 401 на любом другом
маршруте (в том числе `/api/assistant/*` и выдаче токенов), а токен расширения — 401 на `/api/mcp`.

### Фронтенд
`features/assistant/`: маскот «Стік» (`mascot/`: skeleton, ik, springs, physics, effects, face, ink, animations, brain,
engine, renderer, loop — чистые модули с тестами; 12 появлений, 12 idle, 6 уходов, 17 движений, 17 занятий, перетаскивание и бросок с физикой),
чат `chat/` (карточка подтверждения записи, панель MCP с предупреждением о правах токена), диктовка `voice/`
(MediaRecorder webm/opus → mp4 → ogg, 24 кбит/с, ≤ 120 с, ≤ 4 МБ; `POST /transcribe`, опрос каждые 2 с до 90 с;
текст только вставляется в поле ввода). Монтируется в `ShellLayout` лениво (когда браузер простаивает) и только если у
пользователя есть модуль `assistant`; пункт меню пользователя «Поговорити зі Стіком». Включение/выключение
(`sinhrm.assistant.enabled`, выключенный — круг с глазами за курсором в правом нижнем углу) и лёгкий режим
(`sinhrm.assistant.lite`) — в localStorage; история чата — в sessionStorage (последние 40 сообщений, ключ
`sinhrm.assistant.history.<userId>`; в ней и ответы инструментов, то есть данные API). История удаляется при выходе
(`clearAssistantHistory()` в `shell.layout.ts` → `logout()`) и при входе пользователя во вкладке (`AssistantConversation`
следит за `AuthService.user`): удаляются истории ВСЕХ других пользователей (ключи `sinhrm.assistant.history.*`, кроме
своего), в том числе оставшиеся после истёкшей сессии и перезагрузки; перезагрузка страницы тем же пользователем
свою историю сохраняет. Клиентские
инструменты: `api_get`, `api_write` (только после «Виконати»), `open_page`; защита путей повторяет бэкенд.
**Падения (v2):** перетаскивание — настоящее физическое удержание: при нажатии берётся ближайшая к курсору точка тела
(кисть, голова, стопа, туловище — вся фигура служит зоной захвата), всё тело становится рэгдоллом, а взятая точка
жёстким ограничением тянется к курсору (18 итераций на шаг, при экстремальной скорости — лёгкое отставание, кости не
растягиваются). Остальное движется только через суставы: за руку он висит на руке, за стопу — вниз головой, раскачивается
маятником, отстаёт от рывков и перелетает при остановке; свободными руками и ногами слабо дрыгается («мышечный» толчок,
не подмена позы), на лице удивление, потом недовольство. Отпустили — бросок возникает из собственных скоростей точек
рэгдолла (никакого отдельного импульса).
После броска, поскальзывания на банановой кожуре, спотыкания или «обморока» включается рэгдолл (`mascot/ragdoll.ts`:
12 точек Верле, связи-кости и мягкие ограничения суставов, гравитация, сопротивление воздуха, пол и стены с трением и
отскоком, вращение броска сохраняется) — он кувыркается и ложится на спину, лицом вниз или на бок. Рисуется ровно
физика; затем поза подбирается по точкам (`fitPose`, лицо определяется по сгибу коленей), и `mascot/getup.ts` поднимает
его ИЗ ЭТОЙ ПОЗЫ: перекат → упор руками → колено → присед → стоя (ключи с IK, длительность сегмента растёт с дальностью
движения, поза не уходит под пол). Все переходы непрерывны: смешивание начинается с текущей позы, углы
разворачиваются по кратчайшему пути, смена направления — плавный разворот, а не зеркальный скачок. После жёсткого
падения — облако пыли, «ой»-реплика (`assistant.ouch.*`), спиральные глаза и звёзды, потирание головы; 3 броска за 20 с —
сидит, скрестив руки, и дуется, потом встаёт. При `prefers-reduced-motion` таскать его можно, но после отпускания
никаких кувырков и сценок — за ≤ 0,2 с он плавно встаёт там, где его отпустили. Изменение размера окна во время падения,
удержания или лёжа — тело переносится внутрь новых стен и оседает на новый пол без скачка. Потерянный захват (потеря
pointer capture, уход фокуса с окна, скрытая вкладка, `pointercancel`) — он просто падает, без скорости броска.
**Шутки после падения:** как только он снова на ногах (сразу после подъёма, до потирания головы и отряхивания), с вероятностью ~70 % шутит в облачке — не
во время ответа чата и не пока пользователь печатает. Ситуация берётся из причины падения: бросок → `thrown`, банан →
`slip`, остальное (спотыкание, «обморок», выпавший захват) → `fall`. Шутки от ИИ (`GET /api/assistant/quips`) грузятся
в фоне, когда браузер простаивает, — по разу на ситуацию и язык интерфейса за сессию, заново при смене языка
(`features/assistant/jokes.ts`); выбор без повтора последних 5. Пустой пул, ИИ выключен или 429 — встроенные шутки
`assistant.jokes.<ситуация>.0–5` (uk/ru/en). При `prefers-reduced-motion` падений нет, поэтому и шуток нет. С открытым чатом после подъёма он запрыгивает обратно на край панели (дугой, без телепорта) и садится; если над панелью нет места, облачко встаёт сбоку от головы.
**Движения и занятия** (`mascot/moves.ts`, `mascot/activities.ts`, общий «сборщик фаз» `mascot/phases.ts`): по нижнему
краю он перемещается по-разному — бег с работой рук, спринт со шлейфом пыли, вприпрыжку, на цыпочках крадучись, лунная
походка, на четвереньках, колесом, кувырком, с сальто назад в конце, скольжением на коленях, на руках; на скейте (толчки,
качение, олли), моноцикле (качается), самокате, пого-палке; с края экрана — раскачивается на руках по верхнему краю и
спрыгивает (как появление), забегает на боковой край и делает сальто назад. Движения выбираются для прогулок по экрану,
появлений и уходов (на уходе движение довозит его до места у бокового края, но не за край — дальше уход через сцену, см. ниже). Занятия в паузах (3–8 с, с комичными промахами): йо-йо (вниз-вверх, «вокруг света», «прогулка с
собакой» — щёлкает по руке), набивание мяча (последний удар по голове), скакалка (запутывается), бумажный самолётик
(летит через экран и падает обратно), мыльные пузыри (последний лопается в лицо), кофе с паром, газета (выглядывает на
курсор), ноутбук, танец, медитация с парением, стойка на голове, фокус со шляпой (цветок или кролик), рыбалка с края
панели чата (только когда сидит на ней), воздушный змей (в «ветреный» день), селфи со вспышкой, помахать курсору,
рисунок на «стекле» и стирание. Разнообразие: мозг помнит последние 6 выборов (занятия, движения, мелкие жесты) и не
повторяет их; утром чаще кофе, поздно вечером — зевает и потягивается (по местному времени, никуда не отправляется);
в лёгком режиме — без пузырей, змея и транспорта; при `prefers-reduced-motion` новых движений нет. Каждое движение и
занятие начинается с текущей позы и кончается известной позой (стоя в точке назначения / там же, рыбалка — сидя), тест
непрерывности (< 40 px/кадр) покрывает все. Реквизит — те же чернильные пути (≤ 24), `pointer-events: none`. Замер:
в среднем ≈ 0,04–0,07 мс на кадр (движок + отрисовка), худший кадр обычно ≤ 1 мс; в синтетическом прогоне без пауз
изредка бывают всплески сборки мусора до ~10 мс.

**Уходы внутри сцены** (`mascot/exits.ts`, обрезка фигуры — `mascot/mask.ts`): он больше не уходит за край экрана —
уходит через то, что рисует чернилами прямо рядом с собой (рисунок «проявляется» штрих за штрихом, в конце стирается/гаснет):
**дверь** (рамка на линии пола; открывается с перспективой, он входит, дверь закрывается; варианты — сначала стучит;
оборачивается из проёма и машет), **люк** (круглый, поднимает крышку и отбрасывает её за спину, спускается по
лестнице внутри, крышка съезжает обратно), **портал** (спираль; он ныряет в неё, крутясь и уменьшаясь, спираль
схлопывается), **лифт** (жмёт кнопку — «динь», двери разъезжаются, заходит, машет, двери закрываются), **люк-ловушка**
(стоит, насвистывая, — под ним открывается створка, секунда в воздухе с изумлённым лицом, падает, створка захлопывается),
**ластик** (достаёт огромный ластик и стирает себя от ступней вверх). Исчезает он именно «в» дверь или дыру: фигура и
тень обрезаются SVG `clipPath` (проём двери/лифта, диск портала, линия ластика; у люка скрыто всё ниже переднего края
отверстия), за край вьюпорта ничего не уезжает; на время обрезки зона захвата отключена. Выбор взвешенный и без повтора
подряд; уход «движением» (бег, скейт…) останавливается у края и продолжается одним из этих уходов. Выглянул, а его
заметили, — тоже уходит через дверь/люк рядом. Три ухода работают и как появления: выходит из двери, вылезает из люка,
вылетает из портала. В лёгком режиме — только простые дверь и люк (и среди появлений), без проявления штрихами; при
`prefers-reduced-motion` уходов и появлений нет, как и раньше; при открытом чате он не уходит. Реквизит — пул чернильных
путей (≤ 24), `pointer-events: none`, исчезает с затуханием. Тесты `exits.spec.ts`: непрерывность (< 40 px/кадр) каждого
ухода и появления из разных поз (стоя, у края, выглядывая из-за края, сидя на чате), в конце ухода ни один сустав и
контур головы не видны вне двери/дыры, в начале появления он скрыт, без повторов подряд, лёгкий режим, reduced motion;
замер в реалистичном цикле (16,7 мс) — в пределах бюджета (p99 ≤ 1 мс).

**Ничего не вылетает при перетаскивании:** «линии скорости» (палочки каждые 0,06 с при скорости > 650 px/с, длиной ∝ скорости — при рывке мышью до ~270 px) рождались и во время хвата, давая артефакты-«лучи»; эффект удалён целиком. Эффекты появляются только после отпускания (пыль и звёзды при ударе) и в анимациях (капли пота, «!», кольца, верёвка, банан). Тест `falling.spec.ts`: при быстром перетаскивании и в полёте до удара — ни одного эффекта.

**Пути на окно чата** (`mascot/seat-routes.ts`): когда «Стіку» нужно на верхний край панели чата (чат открыли, пока он на
экране; поднялся после падения при открытом чате; закончил появление при открытом чате), он выбирает один из маршрутов:
прыжок дугой (только близко и невысоко), лезет по боковой кромке панели руками и ногами (IK), рисует карандашом
лестницу и поднимается по ступеням, канат падает сверху — лезет и раскачивается маятником на панель, рисует батут и
прыгает 2–3 раза всё выше, надувает шарик, всплывает и лопает его булавкой над панелью («ой»), прыжок с шестом, лесенка
из ступенек, которые дорисовываются под ногами. Выбор — по геометрии (расстояние, высота верха панели над полом, место
сбоку, панель у верхнего края экрана) с весами и без повтора подряд; в лёгком режиме только прыжок, ступеньки и
лазание, без эффекта дорисовки; при `prefers-reduced-motion` — короткое линейное смешивание сразу на место, без
реквизита. Маршрут — чистая функция времени (фазы с плавными стыками), начинается с текущей позы и кончается ровно
позой сидя; длится ~1,5–4 с, дольше — при ходьбе издалека или высокой панели (до ~5,8 с: лазание не быстрее
230 px/с, маршруты длиннее этого не предлагаются). Каждый маршрут знает, сколько места сбоку от панели ему нужно
(ступеньки — по числу ступеней из общей функции, канат — с учётом обратного размаха, шест — по длине шеста), и
предлагается, только если он сам, его руки/ноги и реквизит остаются в пределах окна; если не подходит ничего (панель-шторка
на телефоне во всю ширину) — прыжок прямо вверх. Прибыв на край широкой панели, он встаёт и доходит по её верху до места. Реквизит — чернильные пути в мировых координатах,
`pointer-events: none` (чат остаётся кликабельным), тает за 0,45 с после маршрута или при прерывании. Закрыли чат на
середине: в воздухе (канат, лестница, шарик) он отпускается и падает (рэгдолл → подъём), на полу — просто переходит к
следующему действию. Панель сдвинулась или окно изменило размер — прямоугольник панели перечитывается один раз, цель
маршрута плавно подтягивается к новому месту. Потолок смешивания между любыми двумя клипами поднят с 0,7 до 1,1 с
(большие перемещения, например повторное открытие чата далеко под панелью, иначе прыгали > 40 px/кадр), поэтому
крупные переходы и вне маршрутов стали немного медленнее; reduced motion не затронут. Замер: самый тяжёлый маршрут (шарик) ≈ 0,014 мс движок + 0,04 мс
отрисовка на кадр, худший кадр ≈ 1 мс. Пока чат ждёт ответа (ход, опрос, инструменты, карточка
подтверждения) или идёт запись/распознавание голоса, он не засыпает — таймер бездействия сбрасывается, поза «думаю»
остаётся, с короткими сменами (постукивает по подбородку, смотрит вверх, кивает «хм»); новый запрос будит спящего. Замер: шаг рэгдолла ≈ 0,02–0,03 мс, шаг удержания (18 итераций) ≈ 0,03–0,04 мс, кадр со всей отрисовкой
≈ 0,1 мс; тест непрерывности: смещение любого сустава между кадрами < 40 px (во время падения — ровно точки физики).
**Бюджет производительности:** цикл анимации идёт только пока маскот на экране и вкладка видима (выключенный круг,
скрытая вкладка, `prefers-reduced-motion` — без цикла), 30 кадр/с спокойно / 60 в быстром движении / 10 во сне / 30 в
лёгком режиме, без SVG-фильтров, дрожание линии 8 Гц, ≤ 12 частиц; пауза при вводе вне чата и при открытом диалоге;
слабое железо или долгие кадры → лёгкий режим автоматически. Замер: спокойный кадр ≈ 0,06 мс скриптов, пик ≈ 1,4 мс.

### Общие примитивы фронта
Общий код фронта лежит в `frontend/src/app/core` ([core.md](core.md)); фича его только вызывает.
- HTTP-сервис фичи снимает обёртку ответа `{ data }` общим оператором `unwrapData()` (`core/api/unwrap-data.ts`, тип `DataEnvelope<T>` из `core/api/api.model.ts`) вместо своего `map((r) => r.data)`; параметры запроса без пустых значений — `toParams` из `core/api/http-params.ts`, страница списка — `Paged<T>` оттуда же. Контракт API не менялся.

## Как проверить
- Mobile flow открытия/закрытия чата в `e2e/flows.pw.ts` отвечает только на один синтетический `GET /api/assistant/status` на локальном origin теста: `{ data: { available, reason, mcp_url } }`. Проверки незаписанных GET и отсутствия записей остаются строгими; ход AI и MCP не вызываются.
- `tests/Feature/Assistant/AssistantChatTest.php` — статус, ход с серверным и клиентским инструментами (тело запроса к
  брокеру: tools, `tool_choice`, без `response_format`, стабильный system, контекст в последнем user), текстовый ответ и
  пересылка истории инструментов, неизвестный инструмент → повтор → `ai_invalid_output`, отложенный ход и опрос только
  владельцем, выключенный ИИ без вызова провайдера, валидация истории, гость → 401.

## Доступ к модулю
Ключ модуля `assistant`. По умолчанию: включён, все роли. Выключенный модуль отвечает 403 `module_disabled` и на
`/api/assistant/*`, и на `/api/mcp`; Стік в интерфейсе не показывается. Подробнее — [modules-access.md](modules-access.md).

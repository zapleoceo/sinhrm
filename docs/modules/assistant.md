# Модуль Assistant (помощник «Стік»)

## Что это и зачем
«Стік» — нарисованный человечек-помощник, который живёт поверх интерфейса: иногда сам выходит из-за края экрана
(выглядывает, вылезает, выпрыгивает, падает сверху), реагирует на курсор и на то, что происходит, и с ним можно
поговорить. Он отвечает на вопросы по работе в SinHRM, находит данные, объясняет «как сделать» и сам выполняет
действия — **строго с правами того, кто с ним говорит**, а любое изменение данных только после клика «Виконати».

Тот же набор инструментов доступен внешним AI-клиентам (Claude Desktop, Claude Code, любой MCP-клиент) через
**MCP-сервер** `POST /api/mcp` — по личному токену пользователя.

## Как пользоваться
- Нажмите на Стіка (или на маленький круг с глазами в правом нижнем углу, если он выключен) — откроется чат.
  Пишите как человеку: «Хто зараз на етапі оферу?», «Скільки днів відпустки в мене лишилось?», «Переведи Олену
  на Е-співбесіду». Для изменений Стік показывает карточку «що саме зміниться» — выполняется только после «Виконати».
- Меню чата: «Нова розмова», вкл/выкл Стіка (выключенный — круг с глазами, которые следят за курсором; сам не
  выходит), «Підключити до Claude / MCP».
- **Подключение к Claude.** Меню чата → «Підключити до Claude / MCP» → «Створити токен» (показывается один раз) →
  скопировать готовую команду, например
  `claude mcp add --transport http sinhrm https://<домен>/api/mcp --header "Authorization: Bearer <токен>"`.
  Токен: 90 дней, один на пользователя (новый отзывает старый), «Відкликати» — сразу.
- Если ИИ выключен в админке (глобальный выключатель, интеграция AI Broker или переключатель «ШІ: помічник Стік»),
  Стік продолжает жить и шутить, а в чате объясняет, почему не может ответить.

## Как устроено

### Инструменты (один набор для чата и MCP)
`Contracts/AssistantTool` — имя, описание, JSON-схема аргументов, где выполняется в чате (`Enums/ToolRunner`:
`Server` | `Client`), меняет ли данные, доступен ли по MCP, `run(User, args)`. Классы тегируются
`AssistantServiceProvider::TOOLS_TAG` — **любой модуль может добавить свой инструмент**. `Support/ToolRegistry`
отдаёт их отсортированными (побайтно стабильный список — часть кешируемого префикса промпта).

| Инструмент | Чат | MCP | Что делает |
|---|---|---|---|
| `find_endpoints` | сервер | да | поиск по живой карте API (`Support/EndpointCatalog`) |
| `api_get` | браузер | да (read-only) | GET любого разрешённого эндпоинта |
| `api_write` | браузер, **после подтверждения** | да (destructive) | POST/PUT/PATCH/DELETE; `summary` — текст карточки подтверждения |
| `open_page` | браузер | нет | открыть страницу SPA |

**Карта API** (`EndpointCatalog`) строится из таблицы маршрутов Laravel при вызове, а не из списка в коде: каждый
новый эндпоинт любого модуля доступен Стіку сразу. В неё попадают только маршруты `api/*` с `auth:sanctum` из модулей,
которые пользователь может открыть (`ModuleAccess`), без закрытых префиксов. Для каждого: метод, путь, модуль, первая
строка docblock экшена контроллера и правила его FormRequest (поля тела; для GET — параметры запроса).

**Закрытые пути** (`Support/ApiPath`, зеркало во фронте `assistant-tools.ts`): `ops`, `mcp`, `assistant`, `auth/logout`,
`sanctum`, `clipper`, `public`, `me/extension-token`, `webhooks`; запрещены `..`, `//`, абсолютные URL. Всё остальное
всё равно проходит проверку доступа к модулю, гейты и политики — список только убирает то, что ИИ трогать не должен.

### Чат (`/api/assistant/*`, сессия)
Сервер **без состояния**: историю хранит SPA и сама ведёт цикл. Один `POST /api/assistant/turn` = **ровно один** вызов
модели через `AiService` (ворота AI, дневные лимиты, запись в `ai_requests`, без логирования промптов), поэтому каждый
запрос укладывается в 60 с Vercel (ожидание модели ≤ 25 с).
1. SPA шлёт `{messages, page: {path, title}}` (формат сообщений OpenAI: user / assistant с `tool_calls` / tool).
   По умолчанию (`native_tools = off`) инструменты уходят модели не нативно, а через эмуляцию строгим JSON
   ([ai.md](ai.md), «Эмуляция tools») — ход может обслужить любой живой провайдер брокера; для чата разницы нет.
2. `Services/AssistantChatService` собирает промпт (`Ai/AssistantPrompt`) и вызывает `AiService::run`
   (цель `AiPurpose::AssistantChat`, subject `assistant_user` + id пользователя).
3. Ответ модели проверяет `Ai/AssistantChatHandler` (реализует `AiConversationHandler`): только известные инструменты,
   аргументы — JSON-объект, ≤ 8 вызовов, не пустой ответ; иначе один повтор, затем `ai_invalid_output`.
4. Вызовы `Server` выполняются сразу → `server_results`; вызовы `Client` → `client_calls`. SPA выполняет их своей
   сессией (запись — только после клика), дописывает результаты и шлёт следующий ход; текст без вызовов — финальный
   ответ. Лимит во фронте — 8 ходов на одно сообщение.
5. Не успел за 25 с → `{state: pending, request_id}`; SPA опрашивает `GET /api/assistant/turns/{id}` (только владелец,
   чужой — 404). Готовый ход держится в кеше 15 мин (`assistant.turn.<id>`), так что его заберут и после `ai.poll`.

История от клиента **ничего не исполняет**: сервер выполняет только новые вызовы модели и только с правами
пользователя. `TurnRequest` проверяет форму и размер (≤ 60 сообщений, ≤ 14 000 символов на сообщение, последнее — от
пользователя или инструмента, роль `system` запрещена).

### Диктовка голосом
Кнопка-микрофон в чате записывает голос (MediaRecorder, ≤ 120 с, ≤ 4 МБ — лимит тела запроса Vercel 4,5 МБ) и шлёт в
`POST /api/assistant/transcribe`. `Services/AssistantVoiceService` → `AiService::transcribe` (цель
`AiPurpose::AssistantVoice`, **тот же выключатель `ai_assistant_chat`**, общие дневные лимиты, строка в `ai_requests` с
`capability = transcription`) → брокер `POST /v1/transcribe/jobs` (Whisper: local → groq → gemini → openai). Ответ
брокера ждём ≤ 25 с; медленный (запасной локальный Whisper — до ~2,5 мин) → `pending`, SPA опрашивает
`GET /api/assistant/transcriptions/{id}` (только владелец, 15 мин в кеше — `Ai/AssistantVoiceHandler`). Текст
**вставляется в поле ввода** — пользователь правит и отправляет сам; тишина → `empty_transcript`. Аудио SinHRM не
хранит (передаётся один раз под нейтральным именем `voice.<ext>`; брокер удаляет его по завершении задачи).
Лимит — 10 записей/мин на пользователя. У ключа проекта в брокере должна быть область `transcription`, иначе ответ
`ai_provider_http_403` — **на живом брокере не проверялось**.

### Промпт `assistant.v1` и кеширование
Текст — `AssistantPrompt::SYSTEM` (ROLE → TASK → RULES → APP MAP → OUTPUT, английский; ответ — на языке пользователя).
Смена текста = новая версия `VERSION`. В `system` и описаниях инструментов нет дат, имён, id и данных страницы;
контекст хода (`user <имя>, roles; today <дата>; current page <путь> «<заголовок>»`) дописывается в начало
**последнего** сообщения пользователя. Стабильный префикс (system + tools) ≈ 6 000 символов ≈ 1 500 токенов. В
`chat:smart` брокер с tools идёт `gemini/gemini-2.5-flash` → `anthropic/claude-sonnet-5` (брокер,
`litellm_adapter.DEFAULT_MODEL`): для Sonnet 5 префикс выше минимума кеша (1024), `cache_control` ставит брокер.
**Проверить кеш по `ai_requests.tokens_cached` сейчас нельзя:** брокер сохраняет `cache_read_tokens` в метаданных
задачи (`job_queue.py`), но не отдаёт это поле в ответе `GET /v1/jobs/{id}` (`DeepJobResponse`) — у всех целей SinHRM
там 0 независимо от реального кеша. Нужна правка в брокере. На живом брокере ход с tools не проверялся (нет ключа
в среде разработки).

### MCP-сервер (`POST /api/mcp`)
`Mcp/SinhrmMcpServer` на официальном пакете `laravel/mcp` (MIT, Streamable HTTP, JSON-RPC). Инструменты — те же
`AssistantTool` с `overMcp() = true`, обёрнутые `Mcp/BridgedTool` (та же схема, подсказки `readOnlyHint` /
`destructiveHint`). Вызов выполняет `Services/InternalApi`: подзапрос проходит через роутер со **всеми** middleware
маршрута (доступ к модулю, гейты, политики, валидация) от имени владельца токена; ответ обрезается до 12 000 символов.
Middleware: `auth:sanctum`, `EnsureUserIsActive`, доступ к модулю `assistant`, `throttle` 60/мин на токен.
В OpenAPI (`/api/docs`) маршрут не попадает — это не REST.

### Токены
`Services/McpTokenService`: имя `mcp`, ability `mcp`, 90 дней, один на пользователя — поверх общих
`Auth/Services/PersonalTokens` (те же, что у токена расширения, [auth.md](auth.md)). Где токен принимается, решает
`Auth/Support/TokenScopes`: модуль регистрирует `api/mcp → mcp`, поэтому MCP-токен получает 401 на любом другом
маршруте (в том числе `/api/assistant/*` и выдаче токенов), а токен расширения — 401 на `/api/mcp`.

### API
| Метод | Ответ |
|---|---|
| `GET /api/assistant/status` | `{available, reason, mcp_url}`; `reason`: `ai_disabled` \| `ai_not_configured` \| `ai_purpose_disabled` |
| `POST /api/assistant/turn` (20/мин) | `{state: done\|pending\|failed, request_id, assistant?, server_results?, client_calls?, error?}` |
| `GET /api/assistant/turns/{id}` | то же для отложенного хода; чужой — 404 |
| `POST /api/assistant/transcribe` (multipart `audio`, 10/мин) | `{state: done\|pending\|failed, request_id, text?, error?}` |
| `GET /api/assistant/transcriptions/{id}` | то же для отложенной расшифровки; чужая — 404 |
| `GET` / `POST` / `DELETE /api/assistant/mcp-token` | статус; 201 с `token` (один раз); 204 |
| `POST /api/mcp` | MCP (JSON-RPC), только `Authorization: Bearer <mcp-токен>` |

Настройки в интеграции AI Broker: `capability_assistant_chat` (по умолчанию `chat:smart`: нативные tools в брокере есть только у openai/anthropic/gemini/mistral — в `chat:fast` остался бы один бесплатный gemini, в `chat:smart` — gemini, затем anthropic) и выключатель
`ai_assistant_chat` (`on`) — [ai.md](ai.md). Каждый ход — одна попытка в дневном лимите `max_requests_per_day`.

### Фронтенд
`features/assistant/`: маскот «Стік» (`mascot/`: skeleton, ik, springs, physics, effects, face, ink, animations, brain,
engine, renderer, loop — чистые модули с тестами; 9 выходов, 12 idle, 5 уходов, перетаскивание и бросок с физикой),
чат `chat/` (карточка подтверждения записи, панель MCP с предупреждением о правах токена), диктовка `voice/`
(MediaRecorder webm/opus → mp4 → ogg, 24 кбит/с, ≤ 120 с, ≤ 4 МБ; `POST /transcribe`, опрос каждые 2 с до 90 с;
текст только вставляется в поле ввода). Монтируется в `ShellLayout` лениво (когда браузер простаивает) и только если у
пользователя есть модуль `assistant`; пункт меню пользователя «Поговорити зі Стіком». Включение/выключение
(`sinhrm.assistant.enabled`, выключенный — круг с глазами за курсором в правом нижнем углу) и лёгкий режим
(`sinhrm.assistant.lite`) — в localStorage; история чата — в sessionStorage (последние 40 сообщений). Клиентские
инструменты: `api_get`, `api_write` (только после «Виконати»), `open_page`; защита путей повторяет бэкенд.
**Падения (v2):** перетаскивание — настоящее физическое удержание: при нажатии берётся ближайшая к курсору точка тела
(кисть, голова, стопа, туловище — вся фигура служит зоной захвата), всё тело становится рэгдоллом, а взятая точка
жёстким ограничением тянется к курсору (18 итераций на шаг, при экстремальной скорости — лёгкое отставание, кости не
растягиваются). Остальное движется только через суставы: за руку он висит на руке, за стопу — вниз головой, раскачивается
маятником, отстаёт от рывков и перелетает при остановке; свободными руками и ногами слабо дрыгается («мышечный» толчок,
не подмена позы), на лице удивление, потом недовольство. Отпустили — бросок возникает из собственных скоростей точек
рэгдолла (никакого отдельного импульса). Из тела вылетают нарисованные стрелки по направлению рывка (сглаженная скорость
мыши; в лёгком режиме меньше, при `prefers-reduced-motion` нет; при резком броске — залп из 3–5 стрелок).
После броска, поскальзывания на банановой кожуре, спотыкания или «обморока» включается рэгдолл (`mascot/ragdoll.ts`:
12 точек Верле, связи-кости и мягкие ограничения суставов, гравитация, сопротивление воздуха, пол и стены с трением и
отскоком, вращение броска сохраняется) — он кувыркается и ложится на спину, лицом вниз или на бок. Рисуется ровно
физика; затем поза подбирается по точкам (`fitPose`, лицо определяется по сгибу коленей), и `mascot/getup.ts` поднимает
его ИЗ ЭТОЙ ПОЗЫ: перекат → упор руками → колено → присед → стоя (ключи с IK, длительность сегмента растёт с дальностью
движения, поза не уходит под пол). Все переходы непрерывны: смешивание начинается с текущей позы, углы
разворачиваются по кратчайшему пути, смена направления — плавный разворот, а не зеркальный скачок. После жёсткого
падения — облако пыли, «ой»-реплика (`assistant.ouch.*`), спиральные глаза и звёзды, потирание головы; 3 броска за 20 с —
сидит, скрестив руки, и дуется, потом встаёт. Замер: шаг рэгдолла ≈ 0,02–0,03 мс, шаг удержания (18 итераций) ≈ 0,03–0,04 мс, кадр со всей отрисовкой
≈ 0,1 мс; тест непрерывности: смещение любого сустава между кадрами < 40 px (во время падения — ровно точки физики).
**Бюджет производительности:** цикл анимации идёт только пока маскот на экране и вкладка видима (выключенный круг,
скрытая вкладка, `prefers-reduced-motion` — без цикла), 30 кадр/с спокойно / 60 в быстром движении / 10 во сне / 30 в
лёгком режиме, без SVG-фильтров, дрожание линии 8 Гц, ≤ 12 частиц; пауза при вводе вне чата и при открытом диалоге;
слабое железо или долгие кадры → лёгкий режим автоматически. Замер: спокойный кадр ≈ 0,06 мс скриптов, пик ≈ 1,4 мс.

## Как проверить
- `tests/Feature/Assistant/AssistantChatTest.php` — статус, ход с серверным и клиентским инструментами (тело запроса к
  брокеру: tools, `tool_choice`, без `response_format`, стабильный system, контекст в последнем user), текстовый ответ и
  пересылка истории инструментов, неизвестный инструмент → повтор → `ai_invalid_output`, отложенный ход и опрос только
  владельцем, выключенный ИИ без вызова провайдера, валидация истории, гость → 401.
- `tests/Feature/Assistant/McpServerTest.php` — выдача/статус/отзыв токена, MCP-токен работает только на `/api/mcp`,
  токен расширения и сессия туда не проходят, `tools/list` с подсказками, вызовы через реальный API с правами
  пользователя (403 от политики, закрытый путь, карта без чужих модулей).
- `tests/Feature/Assistant/AssistantVoiceTest.php` — запись → multipart на `/v1/transcribe/jobs` → текст, отложенная
  расшифровка и опрос только владельцем, тишина → `empty_transcript`, выключатель помощника, проверка файла (тип, 4 МБ).
- `tests/Unit/Assistant/ApiPathTest.php`, `tests/Unit/Auth/TokenScopesTest.php`.
- Фронт: `npx ng test --watch=false` — `features/assistant/**` (кинематика, IK, пружины, физика, мозг с фейковыми
  таймерами, отсутствие цикла в выключенном/скрытом состоянии, цикл разговора, защита путей, запись голоса).

## Доступ к модулю
Ключ модуля `assistant`. По умолчанию: включён, все роли. Выключенный модуль отвечает 403 `module_disabled` и на
`/api/assistant/*`, и на `/api/mcp`; Стік в интерфейсе не показывается. Подробнее — [modules-access.md](modules-access.md).

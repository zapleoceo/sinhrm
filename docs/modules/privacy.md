# Модуль Privacy (права на персональные данные)

## Что это и зачем
Закон Украины «О защите персональных данных» (№2297-VI) даёт человеку право узнать, какие данные о нём хранятся, и
потребовать их удалить. Модуль делает это одной кнопкой: **выгрузка** всего, что SinHRM хранит о кандидате или бывшем
сотруднике, и **удаление** (обезличивание) этих данных. Плюс правило хранения: отклонённых кандидатов можно обезличивать
автоматически через N месяцев (по умолчанию выключено).

## Как пользоваться
Только суперадмин и админ.
- **Карточка кандидата** → кнопка «Персональні дані»:
  - «Експорт даних (JSON)» — файл для передачи человеку или другой системе;
  - «Експорт даних (для читання)» — тот же состав в HTML-файле, открывается в любом браузере без интернета;
  - «Видалити персональні дані» — окно с предупреждением «це незворотно», обязательной причиной (например, «письмовий
    запит від 09.10.2026») и галочкой «Я розумію…». После удаления карточка показывает «Видалений кандидат #id».
- **Профиль сотрудника** → та же кнопка. Удаление доступно **только после увольнения** (статус «звільнений»).
- **Меню → Адміністрування → «Персональні дані»** (`/admin/privacy`): переключатель «Автоматично знеособлювати відхилених
  кандидатів» и срок в месяцах (1–120, по умолчанию предлагается 12).

Нельзя удалить: кандидата, которого наняли и который ещё работает (сначала увольнение, потом удаление данных сотрудника),
и работающего сотрудника — сервер ответит 409 (`hired`, `not_terminated`).

## Что выгружается и что стирается

| Где (модуль) | Выгрузка | Удаление |
|---|---|---|
| Recruiting: кандидат | имя, телефон, e-mail, Telegram, город, источник/канал, UTM, теги | имя → «Видалений кандидат #id», контакты и теги стёрты; город, канал, UTM, даты остаются для отчётов |
| Recruiting: ссылки на профили | LinkedIn/Work.ua/… | удаляются |
| Recruiting: отклики | вакансия, этап, статус, причина отказа, заметка к отказу, история этапов с комментариями | заметка к отказу и комментарии этапов стёрты; вакансия, этапы, статусы, даты остаются (воронка, отчёты) |
| Recruiting: касания | сообщения, звонки, заметки, встречи (текст и meta: ссылки на запись, на встречу) | текст, meta и внешний id стёрты; строка (канал, направление, автор, дата) остаётся — счётчики касаний |
| Recruiting: ШІ-скринінг | балл, вердикт, резюме, сильные стороны, пробелы, вопросы | удаляется целиком |
| Scripts | задачи рекрутера о человеке, оценки звонков по скрипту (в них цитаты разговора) | оценки удаляются; заголовок задачи → «Видалений кандидат #id» (строка остаётся для статистики нагрузки) |
| MailAgent | журнал обработанных писем: отправитель, тема | отправитель и тема стёрты |
| People (сотрудник) | профиль: контакты, дата рождения, адрес, контакт на экстренный случай, аватар, доп. поля, запросы на изменение | имя → «Видалений співробітник #id», всё перечисленное стёрто; даты приёма/увольнения, филиал, отдел, должность остаются |
| Documents (сотрудник) | список документов: название, статус, даты, имя/тип/размер файла (сам файл — нет) | неподписанные (чернетка, отправлен, отклонён): текст и файл удаляются. Подписанные и архивные — кадровые документы, хранятся столько, сколько требует закон |

Удаление идёт одной транзакцией во всех модулях (всё или ничего) и повторяемо: второй запуск ничего не ломает.

### Что не нужно трогать и почему
- **Pulse и SafeSpeak** — анонимны по устройству: ответы опросов хранятся без id сотрудника, сообщения SafeSpeak — без
  пользователя и IP ([pulse.md](pulse.md), [safe-speak.md](safe-speak.md)). Связать их с человеком нельзя, поэтому ни
  выгружать, ни удалять нечего.
- **Письма в Gmail и события в Google Календаре** — хранятся в ящике/календаре компании у Google, не в SinHRM. Если человек
  просит удалить и их, это делается в самом Gmail/Календаре.
- **ai_requests** — журнал вызовов ШІ хранит только коды и счётчики, без текста и персональных данных.
- **Кадровые записи сотрудника** (табели, отсутствия, оценки, обращения в Desk, активы, воркфлоу) в этот PR не входят:
  это учёт по трудовому законодательству. Если понадобится — модуль добавляет своего провайдера (ниже), остальное не меняется.

## Как устроено
- Контракт `Core\Contracts\PersonalDataProvider` (`section()`, `blocker()`, `export()`, `erase()`): каждый модуль
  описывает только свои таблицы и регистрируется через `$app->tag([...], PersonalDataProvider::class)` — так же, как
  `ScheduledJob` и `HealthCheck`. Privacy не лезет в чужие таблицы. Субъект — `Core\DTO\DataSubject` (`candidate` | `employee` + id).
- Провайдеры: `Recruiting\Privacy\CandidatePersonalData`, `Scripts\Privacy\ScriptsPersonalData`,
  `MailAgent\Privacy\MailPersonalData`, `People\Privacy\EmployeePersonalData`, `Documents\Privacy\DocumentsPersonalData`.
- `blocker()` — причина отказа (`not_found` → 404, `hired`/`not_terminated` → 409). Отвечает модуль-владелец.
- `Privacy\Services\PersonalDataService` запускает всех провайдеров, пишет журнал `privacy_requests` (кто, что, когда,
  причина, счётчики — без самих данных) и лог `privacy.erased`.
- Колонки `candidates.anonymized_at`, `employees.anonymized_at` — когда стёрли (кандидату показывается в API).
- Правило хранения: `Core\Contracts\RetentionSource` (Recruiting отдаёт кандидатов, у которых все отклики отклонены и
  закрыты раньше срока), задача `privacy.retention` (cron каждые ~30 мин, до 50 человек за запуск), настройка —
  одна строка `privacy_settings.retention_rejected_months` (null = выключено). В журнале такие удаления с `trigger = retention`.

### Эндпоинты (`auth:sanctum` + активный пользователь + gate `privacy-manage`: superadmin, admin; иначе 403)
| Метод | Путь | Что |
|---|---|---|
| GET | `/api/privacy/{candidate\|employee}/{id}/export?format=json\|html` | файл-выгрузка (`Content-Disposition: attachment`) |
| POST | `/api/privacy/{candidate\|employee}/{id}/erase` | `{reason (3–500), confirm: true}` → `{data: {erased, counts}}` |
| GET | `/api/privacy/{candidate\|employee}/{id}/requests` | журнал запросов по человеку |
| GET/PUT | `/api/privacy/settings` | `{retention_rejected_months: 1..120 \| null}` |

### Фронтенд (`frontend/src/app/features/privacy`)
`privacy.service.ts` (API, скачивание через `core/http/api-error.saveBlob`), `privacy-actions.ts` (кнопка-меню, встроена в
карточку кандидата и профиль сотрудника, видна только superadmin/admin), `erase.dialog.ts` (предупреждение, причина,
галочка), `privacy-settings.page.ts` (`/admin/privacy`, `roleGuard('superadmin', 'admin')`). Тексты — `privacy.*` в трёх языках.

## Как проверить
`php artisan test tests/Feature/Privacy` — доступ по ролям, полнота выгрузки (JSON и HTML), удаление стирает каждое
персональное поле (включая файлы документов), отчётные строки остаются, отказ для нанятого/работающего, правило хранения.
Фронт: `privacy.spec.ts`.

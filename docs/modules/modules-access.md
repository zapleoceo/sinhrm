# Доступ к модулям (выключатель модулей)

## Что это и зачем

Не каждой компании нужны все разделы SinHRM сразу. Суперадмин может **выключить модуль для всей компании** (например,
«Опитування», пока опросы не проводят) или **скрыть его от части ролей** (например, «Звернення» — только для HR).
Выключение ничего не удаляет: данные лежат на месте, и после включения всё снова видно как было.

Правило одно на всю компанию: у модуля есть переключатель «Увімкнено» и галочки ролей. Исключений для отдельных людей
нет (решение владельца, [ADR 0009](../adr/0009-module-access.md)).

## Как пользоваться

1. Войдите как суперадмин → «Адміністрування» → **«Модулі»**.
2. В строке модуля включите или выключите «Увімкнено» и отметьте роли, которым модуль виден.
3. Нажмите «Зберегти». При выключении система переспросит: «Вимкнути модуль для всіх? Дані не видаляються».

Базовые модули помечены замком — их нельзя выключить или ограничить: Ядро (Core), Вход и роли (Auth), Користувачі
(Users), Інтеграції (Integrations), Довідники (Directory), Огляд (Overview) с оболочкой интерфейса.

Что видят люди:
- пункты меню выключенного или скрытого для их роли модуля пропадают, пустая группа меню пропадает целиком;
- если открыть такую страницу по ссылке — показывается «Розділ вимкнено» с кнопкой «На головну»;
- суперадмин всегда видит все **включённые** модули, какие бы галочки ни стояли, и всегда видит страницу «Модулі» —
  запереть себя он не может. Выключенный модуль закрыт и для него.

## Роли: простыми словами

Галочка роли — это **дополнительное ограничение**, а не выдача прав. Если роли что-то не разрешено внутри модуля
(например, наблюдателю нельзя редактировать вакансии), галочка этого не изменит.

Контекстные роли — нанимающий менеджер вакансии, интервьюер кандидата, руководитель сотрудников — не отдельные роли в
списке. Человек видит модуль, только если модуль включён **и** отмечена его базовая роль. Пример: сотрудник-нанимающий
менеджер видит «Рекрутинг», только пока у модуля Recruiting отмечена роль «Співробітник». Пользователь без глобальной
роли считается «Співробітником».

По умолчанию (сразу после обновления) всё включено, а роли совпадают с тем, кто пользовался модулем раньше: у
большинства модулей — все роли, у «ШІ» (Ai) и «Поштовий агент» (MailAgent) — только суперадмин (их страницы и так
закрыты правом `manage-integrations`). Поведение системы для людей не меняется, пока суперадмин сам ничего не выключит.

## Как устроено

| Часть | Где |
|---|---|
| Описание модуля: ключ, иконка, группа, `core`, роли по умолчанию | свойства `ModuleServiceProvider` (`$moduleKey`, `$moduleIcon`, `$moduleGroup`, `$coreModule`, `$defaultRoles`), реестр `Core\Services\ModuleRegistry` |
| Ключ | kebab-case папки модуля: `HiringRequests` → `hiring-requests`, `TimeOff` → `time-off` |
| Хранение | таблица `module_settings` (`module` уникальный, `enabled`, `roles` jsonb); миграция Core заполняет значения по умолчанию для всех небазовых модулей; нет строки — берутся значения по умолчанию |
| Проверка на сервере | middleware `Core\Http\Middleware\EnsureModuleAccessible` ставится `ModuleServiceProvider` на все маршруты небазового модуля (и на публичные маршруты Safe Speak) |
| Правила | `Core\Services\ModuleAccess` (`enabled`, `allows`, `allowedKeys`), настройки читаются один раз за запрос |
| Фоновые задачи | `POST /api/ops/jobs/run` пропускает `ScheduledJob` выключенного модуля (модуль определяется по пространству имён класса): `{"ok": true, "skipped": "module_disabled"}` |
| API для интерфейса | `GET /api/auth/me` → `modules`: ключи доступных пользователю модулей |
| Админка | `GET /api/modules`, `PUT /api/modules/{key}` (`{enabled, roles}`), право `manage-modules` (суперадмин) |
| Интерфейс | `features/core/modules.page.ts` (`/admin/modules`), `features/core/module-off.page.ts` (`/module-off`), `moduleGuard` + карта URL → модуль `core/auth/module-map.ts`, скрытие пунктов в `features/shell` |

Ответы сервера:

| Случай | Ответ |
|---|---|
| модуль выключен, пользователь вошёл | 403 `{"message": "module_disabled", "module": "<key>"}` |
| модуль выключен, запрос без входа (вебхуки Channels, анонимная форма Safe Speak) | 404 |
| модуль включён, роль не отмечена | 403 `{"message": "module_forbidden", "module": "<key>"}` |
| попытка выключить или ограничить базовый модуль | 422 `{"message": "module_core"}` |
| неизвестная роль в `roles` | 422 (ошибка валидации `roles.N`) |

`superadmin` всегда сохраняется в `roles`, даже если его не прислали.

Порядок проверок: сначала выключатель модуля, потом роль, потом обычные права модуля (gate, policy, область филиалов).
Счётчики значков меню (если они есть) должны так же пропускать выключенные модули — через `ModuleAccess::allows`.

## Как добавить новый модуль

В провайдере модуля задайте `$moduleIcon`, `$moduleGroup` и, если модуль доступен не всем ролям, `$defaultRoles`;
базовый модуль — `$coreModule = true`. В `frontend/src/app/core/auth/module-map.ts` добавьте префиксы его страниц,
в `features/shell/nav-groups.ts` (`NAV_GROUP_MODULES`) — ключ в группу меню, в словари `modules.names.<key>` на трёх
языках. Строка в `module_settings` не обязательна: без неё действуют значения по умолчанию.

# Дизайн-направление HRM/ATS (recruiter web app, Angular)

Дата: 2026-09-25 (рестайл C «Маршрут» — 2026-10-02, §4.2)
Статус: research/proposal, требует ревью перед имплементацией

> **Рестайл-PR обязаны держать `ui-parity` зелёным** — ни одна кнопка, поле, колонка или заголовок не теряются
> молча: [UI parity: страховка для рестайла](../guides/ui-parity.md).

Цель продукта: рекрутёр должен ощущать «wow, это удобно» — не за счёт визуальных эффектов,
а за счёт скорости выполнения рутинных операций (просмотр/сортировка кандидатов, тач-поинты,
переходы между этапами воронки) без потери фокуса на текущей задаче.

## 2. Принципы дизайна (8–12)

1. **Одна главная задача на экране.** Каждый view отвечает на один вопрос рекрутёра
   («кого звать дальше», «что с этим кандидатом», «что горит сегодня»). Вторичная информация —
   свёрнута, не соревнуется за внимание.
2. **Command palette как страховочная сеть навигации.** Ctrl/Cmd+K открывает поиск по кандидатам,
   вакансиям, действиям («переместить на этап», «назначить интервью») — контекстно-зависимый список,
   шорткат рядом с каждым пунктом (паттерн Linear).
3. **Keyboard-first, но mouse-friendly.** Любое частое действие (переход между кандидатами, смена
   этапа, добавление заметки) — доступно с клавиатуры в 1–2 нажатия, но не требуется: клики работают
   идентично.
4. **Split view список + деталь как базовый layout**, а не модалки/отдельные страницы. Переход между
   карточками кандидатов не должен терять контекст списка (аналог Ashby/Attio record view).
5. **Единая карточка кандидата = единственный источник истины.** Все тач-поинты (звонок, письмо,
   интервью, оценка, смена этапа) — в одном timeline, а не разбросаны по вкладкам разных модулей.
6. **Inline-редактирование + optimistic UI.** Поля карточки редактируются на месте, без модальных окон;
   изменение отображается мгновенно, сохранение — в фоне, ошибка — откатывается с явным тостом.
7. **Спокойная плотность (calm density).** Достаточно воздуха между строками таблицы/списка, но без
   потери информации на экране — плотность настраивается (comfortable/compact), не навязывается.
8. **Focus mode для глубокой работы.** При открытии карточки кандидата/интервью — возможность скрыть
   боковую навигацию и второстепенные панели одним действием (аналог full-screen у Arc).
9. **Один акцентный цвет, приглушённая нейтральная база.** Цвет используется дозированно — для
   действия/статуса, не для декора; статусы этапов воронки кодируются цветом+иконкой (не только цветом
   — доступность).
10. **Inbox-zero триаж для очереди рекрутёра.** Новые отклики/задачи дня — в отдельном триаж-view с
    быстрыми действиями (принять/отклонить/делегировать) с клавиатуры, аналог inbox-триажа почтовых
    клиентов нового поколения.
11. **AI-помощник как контекстная боковая панель, не чат поверх всего.** Подсказки (саммари резюме,
    черновик письма, red flags) — в докируемой панели рядом с карточкой кандидата, не перекрывает
    основной контент.
12. **Motion — функциональный, не декоративный.** Анимация подтверждает причинность действия
    (карточка переместилась → плавный slide, а не resize; smooth 150–200мс), никогда не блокирует ввод
    следующей команды.

## 3. Карточка кандидата с таймлайном тач-поинтов — layout

```
┌─────────────────────────────────────────────────────────────────────────┐
│ ← Список   Иван Петров · Frontend Developer          [Этап: Интервью ▾] │
│           статус-бейдж, источник (LinkedIn/сайт)      [⌘K действия]     │
├───────────────────────────────┬───────────────────────────────────────┤
│ Профиль (inline-editable)     │ Timeline (тач-поинты)                  │
│ ───────────────────────────── │ ───────────────────────────────────── │
│ Контакты, резюме (preview),   │ [Фильтр: Все / Звонки / Письма /       │
│ зарплатные ожидания, теги     │  Интервью / Заметки]  [Свернуть месяц] │
│                                │                                         │
│ Вакансия и воронка             │ ● 24 сен — Интервью с тимлидом          │
│  (мини-канбан этапов,          │   оценка: 4/5, заметка «сильный React» │
│   текущий этап подсвечен)      │ ● 20 сен — Письмо: приглашение          │
│                                │ ● 18 сен — Звонок HR, 12 мин             │
│ Документы (резюме, портфолио) │ ● 15 сен — Отклик получен (источник)    │
│                                │                                         │
│ [+ Заметка] [+ Задача]         │ [+ Добавить тач-поинт]                  │
├───────────────────────────────┴───────────────────────────────────────┤
│ AI-панель (докируемая, справа, сворачивается): саммари резюме,          │
│ соответствие вакансии, черновик письма, red flags                        │
└─────────────────────────────────────────────────────────────────────────┘
```

Ключевые решения:
- Слева — статичный профиль (то, что редко меняется), справа — timeline (то, за чем следят постоянно).
  Это разделение «стабильное / динамическое» снижает когнитивную нагрузку.
- Мини-канбан этапов внутри карточки — не отдельная страница воронки; смена этапа = drag или клик,
  optimistic-обновление, действие пишется в timeline автоматически.
- AI-панель — third column, скрывается по умолчанию на узких экранах и в focus mode.
- Переход между кандидатами списка — стрелками ↑/↓ или j/k без выхода из detail view (список остаётся
  слева в split view на десктопе, поверх на мобиле/планшете).

## 4. Навигация, цвет/типографика, motion

### Навигация
- Левый узкий рейл: Инбокс (триаж) → Кандидаты → Вакансии → Воронки → Отчёты → Команда.
- Command palette (Ctrl/Cmd+K) — глобальный поиск + действия, приоритет №1 в реализации.
- Хлебные крошки минимальны: split view снимает необходимость в глубокой иерархии страниц.

### Цвет и типографика (light + dark)
- Нейтральная база: серая шкала с холодным подтоном (аналог Linear/Attio), 9–10 ступеней, единая для
  light/dark через design tokens (CSS custom properties), а не захардкоженные hex.
- Один акцент (напр. индиго/синий) — для primary-действий, активных состояний, фокус-колец.
- Статусы этапов воронки — вторичная семантическая палитра (взято/отклонено/оффер и т.д.), всегда
  дублируется иконкой/текстом для доступности (не только цвет).
- Шрифт: одна семья с чёткой числовой/табличной цифрой (tabular figures) для списков и таблиц —
  важно для сканирования кандидатов; UI-размеры сдержанные (14–15px база), без декоративных заголовков.
- Dark theme — не инверсия, а отдельная палитра поверхностей (elevation через яркость, не через тени),
  через Angular Material 3 color-roles/surface-containers либо аналогичные CSS-переменные.

### 4.1 Палитра: «чуть больше цвета» (2026-09-29, владелец) — заменена §4.2

> История. С 2026-10-02 действуют значения §4.2 (направление C «Маршрут»); таблица ниже — для сравнения.

Запрос владельца: дизайн слишком чёрно-белый — добавить цвета **совсем немного**, сохранив спокойный
минимализм. Решение: нейтрали получают лёгкий холодный синий подтон, акцент — ровно цвет логотипа,
бирюза — редкий вторичный акцент. Всё задаётся токенами в `frontend/src/styles.scss`
(Material sys-токены через `mat.theme-overrides` + `--app-*`), страницы hex не пишут.

### 4.2 Направление C «Маршрут» (2026-10-02, рестайл, шаги 1–2)

**Концепт.** Найм — это путь: каждый тип этапа воронки — своя «линия метро», кандидат едет от станции к станции,
у сотрудника — «шлях у компанії». Цвет несёт смысл (тип этапа, действие, статус), база — спокойная нейтральная,
язык формы — **линии вместо теней**: рамки 1.5px, пилюли, кольца-«станции». Владелец делегировал выбор; три
независимых судьи выбрали C. Метафору не пережимаем: в текстах интерфейса «станция» — максимум в паре подсказок.

Где живёт: `frontend/src/styles.scss` — `mat.theme` (шрифты), один `mat.theme-overrides` (цвета, шкала текста,
скругления), точечные `mat.*-overrides` (кнопки, поля, чипы, таблицы, табы, диалоги, меню, тултипы, снекбары,
карточки, сайднав, фокус), токены `--app-*` и глобальные паттерны. Страницы hex не пишут; рестайл страниц
происходит через токены, без правок шаблонов.

**Ограничения для следующих шагов рестайла** (условия судей, обязательны для шагов 3–8):

1. **Навигация** — только «широкая рейка 240px с той же линией и станциями»; НЕ иконочная рейка 72/92px
   (подписи uk/ru обрезаются, 5 сворачиваемых групп). Контракты `nav-groups.spec` и `shell.layout.spec` сохраняются.
2. **Дефекты макета не повторять:** поле поиска людей на 390px не сжимать (в макете ~30px, обрезанный
   placeholder) — поиск на телефоне на всю ширину; подписи «Маршрута дня» не должны сталкиваться (дубли «11:00»,
   наложение кругов) — группировать/сдвигать; мини-маршрут из 5 точек на КАЖДОЙ карточке доски — шум при 100+
   карточках → тонкий «хребет» цвета этапа, точки — только у карточки в фокусе/под курсором или компактный
   счётчик; последняя колонка доски, обрезанная у края, — нужен сигнал прокрутки (затухание/тень у края);
   мобильная нижняя навигация и липкие панели никогда не перекрывают контент (`padding-bottom`), высокая липкая
   навигация не съедает экран.
3. **Доступность:** никогда не только цвет (статус = форма/маркер + текст), AA проверен численно в обеих темах,
   видимое фокус-кольцо, `prefers-reduced-motion` соблюдается.
4. **Бюджет эффектов:** одна анимация прорисовки («trace») + одна анимация появления («pop») максимум, только
   `transform`/`opacity`.
5. **Плотность:** рекрутер работает 6–8 часов — плотность списков и доски не ниже текущей; переключатель
   Комфортно/Компактно — только если дёшево (кандидат на шаг 4).

### Motion
- Длительность 120–200мс, easing стандартный (ease-out на появление, ease-in на исчезновение).
- Переходы между этапами кандидата — slide/fade, не мгновенный skip и не тяжёлая 3D-анимация.
- Loading — skeleton, не спиннер, для списков/карточек (ощущение "уже почти готово").
- Ничего не блокирует клавиатурный ввод во время анимации (можно продолжать печатать в палитре).

## 7. Принятые решения по интерфейсу (2026-09-26, владелец)

- **Без горячих клавиш и палитры.** Command palette (Ctrl/⌘+K), кнопка «Пошук» в шапке, навигация j/k/↑/↓/«/» по
  кандидатам и Ctrl/⌘+Enter в композере убраны вместе с подсказками. Пункты 2, 3 и раздел «Навигация» выше —
  исследование, а не текущее поведение; поиск — полями на страницах ([shell.md](../modules/shell.md)).
- **Даты — только выпадающий календарь** Angular Material (`provideAppDates()`, [core.md](../modules/core.md)):
  нативные `<input type="date|datetime-local">` не используются; формат `дд.мм.рррр`, неделя с понедельника.
- **Иконки.** Базовый набор — Material Symbols (действия интерфейса: сохранить, удалить, меню…). Сторонние ресурсы
  (мессенджеры, job-борды, Google, Meta, телефония, AI-провайдеры) — **Font Awesome Free** через
  `@fortawesome/angular-fontawesome` и поштучный импорт иконок из `@fortawesome/free-brands-svg-icons` /
  `free-solid-svg-icons` (tree-shaking; пакет FA — в ленивом чанке, стартовый бандл не растёт). Единственная точка
  использования — `<app-channel-icon>` (`core/ui/channel-icon.ts`): ключ → иконка + цвет бренда; у work.ua / robota.ua /
  Djinni / DOU брендовых иконок во Free нет — портфель с буквой. В одной группе элементов стили не смешиваем
  (например, строка контактов кандидата и лента касаний — целиком FA). Цвет бренда всегда дублируется текстом или
  `aria-label` — смысл не передаётся только цветом.
- **Атрибуция Font Awesome.** Font Awesome Free by Fonticons, Inc. — https://fontawesome.com. Иконки — CC BY 4.0
  (https://creativecommons.org/licenses/by/4.0/), код — MIT; шрифты (не используются, только SVG) — SIL OFL 1.1.
  Брендовые знаки — товарные знаки их владельцев, используются только для обозначения соответствующего сервиса.


## 8. Логотип и страница входа (2026-09-26, владелец)

- **Знак (концепт C).** Скруглённый квадрат 28×28 (`rx 8`) на сетке 32×32 с полем 2px; внутри — кривая «S»,
  **вырезанная** негативным пространством (SVG `mask`, толщина ≈4), опционально бирюзовая точка `#2EC4B6` r 1.8 на
  конце «S» (в mono-версии и фавиконах её нет). Отличительный элемент — именно вырезанная кривая: без клипарта
  людей/папок, без мультицветных градиентов, без «квадрата с буквой». Компонент `<app-logo>`
  (`core/ui/logo.ts`, варианты `mark` / `full`, флаг `mono`), цвет квадрата — `currentColor` = `--app-brand`.
- **Цвета.** `--app-brand`: `#1A5FB4` (light) / `#3584E4` (dark); текст «HRM» — `--app-brand-text`
  (`#1A5FB4` / `#86B4F0`, AA на фоне темы). Словесный знак «SinHRM» — Onest SemiBold (Google Fonts, есть
  кириллица), трекинг +1 %, «Sin» — цвет текста, «HRM» — бренд.
- **Фавиконы.** `public/favicon.svg` (светлый/тёмный вариант через `prefers-color-scheme`), `favicon.ico`
  16/32/48, `apple-touch-icon.png` 180 (на белом), `icon-192/512.png`, `site.webmanifest` (`theme_color #1A5FB4`).
  Растры — сгенерированные файлы в репо; пересборка: `cd frontend && npm i --no-save sharp png-to-ico &&
  node scripts/gen-icons.mjs` (зависимости проекта не добавляются).
- **Страница входа.** Карточка по центру (≤ 26rem, на телефоне — поля 16px), «стекло» `backdrop-filter` с
  непрозрачным фолбэком; внутри сверху логотип и компактный переключатель языка uk|ru|en (в правом верхнем углу
  карточки, не под ней), заголовок, подзаголовок, кнопка Google с фирменной «G» (inline SVG), примечание
  «только по приглашению», короткий слоган. Ошибки `?error=` (не приглашён, заблокирован…) — плашка
  `role=alert` в той же карточке. Фон — размытые пятна цветов темы, дрейфуют только через `transform`,
  при `prefers-reduced-motion` статичны; лёгкая сетка с радиальной маской. Логотип также в шапке сайдбара.

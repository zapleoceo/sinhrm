# Дизайн-направление HRM/ATS (recruiter web app, Angular)

Дата: 2026-09-25
Статус: research/proposal, требует ревью перед имплементацией

Цель продукта: рекрутёр должен ощущать «wow, это удобно» — не за счёт визуальных эффектов,
а за счёт скорости выполнения рутинных операций (просмотр/сортировка кандидатов, тач-поинты,
переходы между этапами воронки) без потери фокуса на текущей задаче.

## 1. Источники и что из них взято

## 2. Принципы дизайна (8–12)

1. **Одна главная задача на экране.** Каждый view отвечает на один вопрос рекрутёра
   («кого звать дальше», «что с этим кандидатом», «что горит сегодня»). Вторичная информация —
   свёрнута, не соревнуется за внимание.
2. **Command palette как страховочная сеть навигации.** Ctrl/Cmd+K открывает поиск по кандидатам,
   вакансиям, действиям («переместить на этап», «назначить интервью») — контекстно-зависимый список,
   шорткат рядом с каждым пунктом (паттерн Linear).
3. **Keyboard-first, но mouse-friendly.** Любое частое действие (переход между кандидатами, смена
   этапа, добавление заметки) — доступно с клавиатуры в 1–2 нажатия, но не требуется: клики работают
   идентично.
4. **Split view список + деталь как базовый layout**, а не модалки/отдельные страницы. Переход между
   карточками кандидатов не должен терять контекст списка (аналог Ashby/Attio record view).
5. **Единая карточка кандидата = единственный источник истины.** Все тач-поинты (звонок, письмо,
   интервью, оценка, смена этапа) — в одном timeline, а не разбросаны по вкладкам разных модулей.
6. **Inline-редактирование + optimistic UI.** Поля карточки редактируются на месте, без модальных окон;
   изменение отображается мгновенно, сохранение — в фоне, ошибка — откатывается с явным тостом.
7. **Спокойная плотность (calm density).** Достаточно воздуха между строками таблицы/списка, но без
   потери информации на экране — плотность настраивается (comfortable/compact), не навязывается.
8. **Focus mode для глубокой работы.** При открытии карточки кандидата/интервью — возможность скрыть
   боковую навигацию и второстепенные панели одним действием (аналог full-screen у Arc).
9. **Один акцентный цвет, приглушённая нейтральная база.** Цвет используется дозированно — для
   действия/статуса, не для декора; статусы этапов воронки кодируются цветом+иконкой (не только цветом
   — доступность).
10. **Inbox-zero триаж для очереди рекрутёра.** Новые отклики/задачи дня — в отдельном триаж-view с
    быстрыми действиями (принять/отклонить/делегировать) с клавиатуры, аналог inbox-триажа почтовых
    клиентов нового поколения.
11. **AI-помощник как контекстная боковая панель, не чат поверх всего.** Подсказки (саммари резюме,
    черновик письма, red flags) — в докируемой панели рядом с карточкой кандидата, не перекрывает
    основной контент.
12. **Motion — функциональный, не декоративный.** Анимация подтверждает причинность действия
    (карточка переместилась → плавный slide, а не resize; smooth 150–200мс), никогда не блокирует ввод
    следующей команды.

## 3. Карточка кандидата с таймлайном тач-поинтов — layout

```
┌─────────────────────────────────────────────────────────────────────────┐
│ ← Список   Иван Петров · Frontend Developer          [Этап: Интервью ▾] │
│           статус-бейдж, источник (LinkedIn/сайт)      [⌘K действия]     │
├───────────────────────────────┬───────────────────────────────────────┤
│ Профиль (inline-editable)     │ Timeline (тач-поинты)                  │
│ ───────────────────────────── │ ───────────────────────────────────── │
│ Контакты, резюме (preview),   │ [Фильтр: Все / Звонки / Письма /       │
│ зарплатные ожидания, теги     │  Интервью / Заметки]  [Свернуть месяц] │
│                                │                                         │
│ Вакансия и воронка             │ ● 24 сен — Интервью с тимлидом          │
│  (мини-канбан этапов,          │   оценка: 4/5, заметка «сильный React» │
│   текущий этап подсвечен)      │ ● 20 сен — Письмо: приглашение          │
│                                │ ● 18 сен — Звонок HR, 12 мин             │
│ Документы (резюме, портфолио) │ ● 15 сен — Отклик получен (источник)    │
│                                │                                         │
│ [+ Заметка] [+ Задача]         │ [+ Добавить тач-поинт]                  │
├───────────────────────────────┴───────────────────────────────────────┤
│ AI-панель (докируемая, справа, сворачивается): саммари резюме,          │
│ соответствие вакансии, черновик письма, red flags                        │
└─────────────────────────────────────────────────────────────────────────┘
```

Ключевые решения:
- Слева — статичный профиль (то, что редко меняется), справа — timeline (то, за чем следят постоянно).
  Это разделение «стабильное / динамическое» снижает когнитивную нагрузку.
- Мини-канбан этапов внутри карточки — не отдельная страница воронки; смена этапа = drag или клик,
  optimistic-обновление, действие пишется в timeline автоматически.
- AI-панель — third column, скрывается по умолчанию на узких экранах и в focus mode.
- Переход между кандидатами списка — стрелками ↑/↓ или j/k без выхода из detail view (список остаётся
  слева в split view на десктопе, поверх на мобиле/планшете).

## 4. Навигация, цвет/типографика, motion

### Навигация
- Левый узкий рейл: Инбокс (триаж) → Кандидаты → Вакансии → Воронки → Отчёты → Команда.
- Command palette (Ctrl/Cmd+K) — глобальный поиск + действия, приоритет №1 в реализации.
- Хлебные крошки минимальны: split view снимает необходимость в глубокой иерархии страниц.

### Цвет и типографика (light + dark)
- Нейтральная база: серая шкала с холодным подтоном (аналог Linear/Attio), 9–10 ступеней, единая для
  light/dark через design tokens (CSS custom properties), а не захардкоженные hex.
- Один акцент (напр. индиго/синий) — для primary-действий, активных состояний, фокус-колец.
- Статусы этапов воронки — вторичная семантическая палитра (взято/отклонено/оффер и т.д.), всегда
  дублируется иконкой/текстом для доступности (не только цвет).
- Шрифт: одна семья с чёткой числовой/табличной цифрой (tabular figures) для списков и таблиц —
  важно для сканирования кандидатов; UI-размеры сдержанные (14–15px база), без декоративных заголовков.
- Dark theme — не инверсия, а отдельная палитра поверхностей (elevation через яркость, не через тени),
  через Angular Material 3 color-roles/surface-containers либо аналогичные CSS-переменные.

### Motion
- Длительность 120–200мс, easing стандартный (ease-out на появление, ease-in на исчезновение).
- Переходы между этапами кандидата — slide/fade, не мгновенный skip и не тяжёлая 3D-анимация.
- Loading — skeleton, не спиннер, для списков/карточек (ощущение "уже почти готово").
- Ничего не блокирует клавиатурный ввод во время анимации (можно продолжать печатать в палитре).

## 5. Angular: варианты компонентной базы

| Библиотека | Лицензия | Живость / статус (2026) | Соответствие направлению | Вывод |
|---|---|---|---|---|
| **Angular Material 3** | MIT (часть Angular) | Официальная, активно развивается Angular-командой; M3 token-based theming (`mat.theme`, surface-containers, shape/motion tokens) с Angular 18+ | Даёт спокойную, предсказуемую базу + нативная поддержка design tokens/dark theme через CSS custom properties; слабее в «кастомных» density-плотных data-таблицах без доп. работы | **Брать как фундамент** (нет лицензионного риска, долгосрочная поддержка), тонко кастомизировать токенами |
| **Spartan/ng (shadcn для Angular)** | MIT | Активный проект (spartan-ng/spartan), 1.0, >55 компонентов, copy-paste подход как у shadcn | Un-styled primitives + Tailwind — даёт максимальный контроль над «calm density» и command-palette-подобными компонентами (cmdk-аналог); хорошо ложится на дизайн Linear-типа | **Рекомендовано для command palette, кастомных data-heavy view (таблица кандидатов, timeline)** — либо как дополнение к Material, либо как основная система, если решаем не тянуть Material вообще |
| **Taiga UI** | Apache 2.0 | Активная организация (taiga-family), >100 компонентов, standalone+signals, CSS-custom-properties theming | Богатый набор готовых сложных компонентов (таблицы, календарь и т.п.), но собственный визуальный язык, который придётся переопределять под «Linear-look» | Резервный вариант, если не хватает времени на кастом — даёт готовые сложные виджеты быстрее |
| **PrimeNG** | С 2026 — **не open source** для новых мажорных версий (репозиторий заархивирован 29.06.2026, PrimeNG 22+ — коммерческая лицензия, $599–799/разработчик); есть бесплатный Community-tier с ограничениями и community-форк OpenNG | Лицензионный риск — плата за разработчика или урезанный community-тир | Конфликтует с `reuse-before-build.md` (проверка лицензии перед использованием) | **Не рекомендуется** для нового проекта без явного бюджетного решения; при выборе — фиксировать как отдельное ADR-решение с указанием стоимости |

**Рекомендация**: Angular Material 3 (theming через design tokens, MIT, нулевой лицензионный риск) как
структурный фундамент (формы, диалоги, базовые контролы) + **Spartan/ng** поверх/рядом для
command palette, таблицы кандидатов и калиброванной под Linear-style плотности верстки. Taiga UI —
запасной вариант, если потребуются готовые сложные виджеты (напр. календарь интервью) быстрее, чем
их можно собрать самим. PrimeNG — не брать, пока не согласован бюджет на коммерческую лицензию
(см. `reuse-before-build.md`: причина отказа явно фиксируется — лицензионные изменения 2026 года).

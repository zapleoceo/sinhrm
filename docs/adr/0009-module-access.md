# ADR 0009 — Выключатель модулей: на всю компанию и по ролям, проверка на сервере

**Статус:** принято (2026-09-26). Подробности — [modules/modules-access.md](../modules/modules-access.md).

**Контекст.** В SinHRM 25 модулей, но компании нужны не все сразу. Нужно уметь выключить модуль целиком или скрыть
его от части ролей, не теряя данных и не ломая существующие права.

**Решение (владелец).** Доступ к модулю = переключатель на всю компанию + видимость по глобальным ролям. Исключений
для отдельных пользователей нет. Настройки — таблица `module_settings`; каждый модуль описывает себя в своём
`ModuleServiceProvider` (ключ, иконка, группа, базовый или нет, роли по умолчанию). Проверка — на сервере: middleware на
всех маршрутах небазового модуля (403 `module_disabled` / `module_forbidden`, 404 для анонимных вызовов), фоновые
задачи выключенного модуля пропускаются. Галочка роли только сужает доступ поверх существующих gate/policy, никогда не
расширяет. Суперадмин видит все включённые модули и страницу настроек. Базовые модули (Core, Auth, Users, Integrations,
Directory, Overview) не выключаются. Интерфейс получает список доступных модулей в `GET /api/auth/me` и прячет меню.

**Последствия.** Значения по умолчанию повторяют нынешний доступ, поэтому после обновления ничего не меняется.
Контекстные роли (нанимающий менеджер, интервьюер, руководитель) проходят по базовой роли — обычно `employee`;
если снять её галочку у Recruiting, такие люди перестанут видеть рекрутинг. Новый модуль автоматически попадает в
реестр и под проверку, достаточно объявить его метаданные. Данные при выключении не удаляются.

**Альтернативы.** Флаги в `.env` (нужен деплой, нет ролей); исключения для отдельных пользователей (сложно объяснить и
проверить, владелец отказался); только скрытие меню во фронтенде (API оставался бы открыт).

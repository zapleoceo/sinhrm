# ADR 0005 — Секреты интеграций в БД через `SecretVault`

**Статус:** принято (2026-09-26). Подробности — [modules/integrations.md](../modules/integrations.md),
[architecture/secrets.md](../architecture/secrets.md).

**Контекст.** Репозиторий публичный. Токены каналов, ключ AI Broker, OAuth Google владелец меняет из интерфейса, без
деплоя; в env Vercel — только инфраструктурные значения (`APP_KEY`, БД, `OPS_SECRET`).

**Решение.** Секреты интеграций хранятся в таблице (`IntegrationSecret`, каст `encrypted` — Laravel `Crypt`,
AES-256 с `APP_KEY`; поле скрыто от сериализации). Расшифрованное значение читается **только** через
`Integrations\Contracts\SecretVault` (`get`, `put`, `forget`, `describe`; реализация `EloquentSecretVault`), другие
модули получают его через DI. Наружу отдаётся только `describe()`: задан ли, когда обновлён, маска `••••` + не больше
4 последних символов.

**Последствия.** Ключи вводятся и меняются в «Інтеграціях» без деплоя и без доступа к коду. Дамп БД без `APP_KEY`
секретов не раскрывает; потеря `APP_KEY` делает их нечитаемыми (ввести заново).

**Альтернативы.** Переменная окружения Vercel на каждый ключ — нужен деплой и доступ к Vercel; внешний менеджер
секретов — лишний сервис при бюджете $0.

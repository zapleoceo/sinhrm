# ADR 0002 — AI только через AI Broker, по «возможности», с воротами и бюджетом

**Статус:** принято (2026-09-26). Подробности — [modules/ai.md](../modules/ai.md).

**Контекст.** Нужны оценка звонков по скрипту, сортировка почты и скрининг кандидатов. Бюджет $0, репозиторий
публичный, ключи моделей не должны попасть в код; конкретные модели и цены меняются быстрее, чем код.

**Решение.** Один вход — `AiService::run`, провайдер по умолчанию — `AiBrokerProvider` (шлюз `aib.zapleo.com`,
`POST /v1/jobs?capability=…` + опрос `GET /v1/jobs/{id}`). Запрос называет **возможность** (`chat:fast` по
умолчанию, отдельно на каждую функцию), а не модель: поле `model` в запрос не попадает, пока суперадмин явно его не
задал, — модель выбирает брокер. Ворота до запроса: общий выключатель `AiPolicy::enabled()` (по умолчанию выключен)
→ ключ в `SecretVault` и интеграция `ai_broker` не `off` → выключатель функции → дневные лимиты
(`max_requests_per_day` 200, `daily_cap_usd` $2; превышение — `ai_budget_exceeded`, HTTP 429). Каждый вызов —
строка `ai_requests` (токены, стоимость, модель из ответа), в логах только id и коды. Результат — подсказка,
решение за человеком.

**Последствия.** Смена модели или поставщика — настройка брокера, не деплой. Расходы ограничены сверху и видны.
Зависимость от одного шлюза: если он недоступен, функции AI не работают (ядро продукта от AI не зависит).

**Альтернативы.** Прямые вызовы Anthropic/OpenAI из кода (ключи и выбор модели в приложении) — отклонено;
`OpenRouterProvider` оставлен запасным провайдером за тем же контрактом `AiProvider`.

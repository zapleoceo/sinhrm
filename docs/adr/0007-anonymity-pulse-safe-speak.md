# ADR 0007 — Анонимность Pulse и Safe Speak обеспечивают данные, а не интерфейс

**Статус:** принято (2026-09-26). Подробности — [modules/pulse.md](../modules/pulse.md),
[modules/safe-speak.md](../modules/safe-speak.md).

**Контекст.** Анонимные опросы и сообщения о нарушениях работают, только если сотрудники верят в анонимность.
Скрыть имя в интерфейсе мало: человек с доступом к БД или к повторяющимся отчётам может вычислить автора.

**Решение.**
- **Pulse:** в анонимном ответе нет id и времени (только день); повторный ответ ловится одноразовым отпечатком от
  соли волны, соль **обнуляется при закрытии**. Пока волна открыта, результатов нет (только диапазон числа ответов);
  закрытие необратимо. Порог `min_group_size ≥ 5` на каждую группу. Против вычитания между волнами —
  `SafeComparison` (разница числа ответов 0 или ≥ min) и снимок аудитории при закрытии (`survey_wave_members`,
  `member` = HMAC от id, связи с ответами нет) + `Core/Support/MembershipDifferencing`: группа видна, только если
  симметрическая разность составов `d = 0` или `d ≥ min` (ловит и замену одного человека на другого).
- **Safe Speak:** автор не хранится; доступ — по коду, показанному один раз, в БД только его HMAC-SHA256; IP не
  хранится (для ограничения частоты — хэшированная корзина адреса); дата без времени.

**Последствия.** Часть отчётов намеренно скрыта (`hidden_reason = "anonymity"`), маленькие отделы видны реже.
Гарантии проверяются тестами. Не покрывается: текст, который выдаёт автора, и журналы хостинга (IP на уровне Vercel).

**Альтернативы.** Анонимность только в интерфейсе (имя скрыто, id хранится) — отклонено; сторонний сервис опросов —
данные у третьей стороны и нет связи с оргструктурой.

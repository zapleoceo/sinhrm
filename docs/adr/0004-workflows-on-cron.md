# ADR 0004 — Движок воркфлоу на cron, без очередей

**Статус:** принято (2026-09-26). Подробности — [modules/workflows.md](../modules/workflows.md).

**Контекст.** Воркфлоу (онбординг, испытательный срок, увольнение) — шаги со сроками «через N дней». Воркеров и
очередей нет ([ADR 0001](0001-hosting-and-stack.md)); cron — раз в ~30 минут ([ADR 0006](0006-cron-via-github-actions.md)).

**Решение.** Шаги — строки в БД с `due_at`. `WorkflowTickJob` (`Core\Contracts\ScheduledJob`, задание
`workflows.tick`) на каждом вызове `POST /api/ops/jobs/run` запускает события `probation_end` (окно 7 дней —
переживает пропуски cron) и выполняет до 50 (`StepRunner::BATCH`) созревших шагов. Шаг сначала **захватывается**
атомарным `UPDATE … WHERE executed_at IS NULL`, поэтому два пересекающихся вызова не выполнят его дважды. Упавший
шаг сам не повторяется — админ нажимает «Повторити».

**Последствия.** Точность — до получаса, и это сказано пользователю. Кроме БД инфраструктуры нет; поведение
детерминировано и покрывается тестами. При большом потоке понадобится больший batch или частота.

**Альтернативы.** Laravel Queue + воркер, внешние движки (Temporal и т. п.) — нужен постоянный процесс, текущий
хостинг его не даёт.

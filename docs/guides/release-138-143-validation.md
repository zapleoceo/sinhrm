## Что должен доказать gate помощника

| Сценарий | Проверяемое свойство | Граница доказательства |
| --- | --- | --- |
| Разрешённый список с фильтром и пагинацией | Реальный API возвращает ожидаемые ID и `meta.total`; серверная проекция сохраняет их и удаляет текст/PII | Детерминированный broker в Feature-тесте; это не оценка качества живой модели |
| Числовая ссылка и навигация | Модельный протокол и браузер могут открыть известную карточку, показать полезный счётчик | Browser E2E использует синтетический assistant response; фактические ACL проверяются отдельно Feature-тестами |
| Закрытое чтение | Фиксированный код отказа без приватного текста; пользователю видны объяснение и разрешённый следующий шаг | UI fixture доказывает отображение; не гарантирует формулировку любого ответа модели |
| Запись | Предложение не меняет данные; отдельное подтверждение делает запрос; отказ не пишет; история не повторяет запись | Новое предложение модели может запросить новое подтверждение. Общего idempotency key / exactly-once нет |
| Отзыв доступа | Проверка до и после ожидания провайдера, перед выдачей кеша и новых tool calls; свежие роли/ветки/известные contextual assignments | Нельзя отозвать уже показанный UI-текст или уже отправленные провайдеру данные; это не атомарный снимок всех ACL |
| Границы записей | Реальные API policies и branch scope; отдельный кандидат с applications двух веток | Текущий API проверяет кандидата как целое и отдаёт все его applications. Минимизация не добавляет независимую ACL к каждому вложенному ID |
| Tenant | Наличие отдельного tenant enforcement и отрицательные cross-tenant сценарии | **НЕ ПОДТВЕРЖДЕНО:** tenant-модели нет. Branch ACL и поддельный tenant selector не доказывают tenant isolation |

Автоматическая история передаёт ID/счётчики, а прямой текст пользователя намеренно передаётся AI.
Задачи, требующие чтения имён, контактов, зарплаты и другого закрытого содержимого из API, не поддержаны.
Уже показанная переписка не очищается при смене effective роли того же пользователя.
`AssistantReleaseGateTest.php` содержит 16 новых Feature cases; дополнительный Core-тест проверяет
обновление кеша ModuleAccess без изменения правил авторизации. Браузерные сценарии в
`assistant-context.pw.ts` проверяют count/navigation/confirm/decline/reload/forbidden/retry на uk/ru/en.
Наличие этих тестов не означает, что их CI завершился успешно: результат публикуется с конкретным SHA в PR144.

# UI parity: страховка для рестайла

Рестайл меняет цвета, шрифты, отступы, вид общих компонентов. Он **не должен** убрать кнопку, спрятать поле,
потерять колонку таблицы, сломать перетаскивание или выпустить контент за край экрана. Проверить это глазами
на ~50 экранах в двух ширинах и двух темах нельзя. Это делает CI-job `ui-parity`.

Код — `frontend/e2e/`. Свои `tsconfig.json` и `eslint.config.mjs`; `ng lint`, `ng test`, `ng build` его не видят.

## Что проверяется

Приложение собирается обычным `npm run build` и открывается в headless Chromium. Бэкенда нет: все ответы
`/api/**` и `/sanctum/**` берутся из закоммиченных фикстур (`frontend/e2e/fixtures/*.json`, синтетические
демо-данные с пометкой « [ТЕСТ]»). Шрифты — из devDependencies (без сети), время зафиксировано на момент записи
фикстур, анимации выключены (`prefers-reduced-motion`). Запуск всегда одинаковый.

Страницы и состояния (меню пользователя, «Працювати як», диалог сотрудника, диалог отказа, выбор человека,
раскрытые группы навигации, мобильное меню, вкладки профиля) перечислены в `frontend/e2e/pages.mjs`.
Каждая — в ширине 1440 и 390 px, в светлой и тёмной теме.

| Проверка | Что ловит | Где эталон |
|---|---|---|
| **Инвентарь** | Всё, чем пользователь может что-то сделать: кнопки, ссылки (с адресом), поля, выпадающие списки, вкладки, переключатели, пункты меню — роль, доступное имя, disabled/checked/expanded. Плюс заголовки, заголовки колонок таблиц, области страницы, число строк/карточек. Список сортируется: **переставить можно, потерять, переименовать, спрятать или выключить — нет.** В тёмной теме инвентарь обязан совпасть со светлой. | `frontend/e2e/__snapshots__/<страница>.<desktop\|mobile>.json` |
| **Ошибки** | Ошибки в консоли, необработанные исключения, упавшие запросы, запрос без фикстуры. | — |
| **Вёрстка** | Горизонтальная прокрутка всей страницы; кнопка/ссылка/поле/заголовок, обрезанные `overflow: hidden` или ушедшие за край экрана без прокрутки. | исключения — `frontend/e2e/layout-allowlist.json` |
| **Доступность** | axe-core, WCAG 2.1 A/AA: число нарушений по каждому правилу не должно вырасти (светлая и тёмная тема отдельно). | `frontend/e2e/axe-baseline.json` |
| **Сценарии** | Перетаскивание на доске кандидатов в колонку этапа → ровно один `POST /api/applications/{id}/move` с `stage_id`; в личную колонку → только `PUT …/personal-column`; форма вакансии: название включает «Створити з ШІ»; диалог сотрудника: ошибки валидации, без горизонтальной прокрутки, ничего не отправляет; выбор человека: поиск после паузы, выбранное имя в поле; отчёт со строкой «Разом»; «Працювати як» со списком ролей и `PUT /api/auth/active-role`; мобильное меню открывается, закрывается и закрывается при переходе; переключатель языка на входе. | `frontend/e2e/flows.pw.ts` |

Скриншоты каждой страницы CI кладёт в артефакт `ui-parity-screens` — для ревьюера, **попиксельно не сравниваются**
(рестайл меняет пиксели намеренно). При падении — HTML-отчёт с трейсами в артефакте `ui-parity-report`.

## Запуск локально

```bash
cd frontend
npm ci
npm run build                     # проверяется именно production-сборка
npx playwright install chromium   # один раз
npm run e2e                       # весь набор; отчёт: e2e/.out/report/index.html
npm run e2e -- --project=desktop-light vacancies   # одна тема/ширина, фильтр по имени
npm run e2e:lint                  # eslint + tsc для e2e/
```

**Порт.** Сборку отдаёт `e2e/serve.mjs` на `127.0.0.1:4317`. Занят (например, второй прогон в соседнем worktree) —
задайте другой переменной окружения `E2E_PORT`: `E2E_PORT=4400 npm run e2e`. Её читают одним местом (`e2e/port.mjs`)
конфиг Playwright (`baseURL`, `webServer`), мок API в `e2e/harness.ts` (пропускает только этот хост, остальное
обрывает) и запись фикстур (`e2e:record`; тогда и `SANCTUM_STATEFUL_DOMAINS=127.0.0.1:<порт>`). Не число 1..65535 —
ошибка при старте. CI переменную не задаёт — там 4317.

Временные файлы — только в `D:\Projects\` (правило 9 в `CLAUDE.md`): перед запуском направьте кеши туда,
например `PLAYWRIGHT_BROWSERS_PATH=D:/Projects/_tmp/sinhrm/cache/pw`, `npm_config_cache=D:/Projects/_tmp/sinhrm/cache/npm`.

## Осознанное обновление эталонов

Новая кнопка, новая колонка, переименование, новая страница — это нормальное изменение, но оно должно
**появиться в диффе PR**, а не пройти молча.

```bash
npm run e2e:update     # перезаписывает __snapshots__/*.json и axe-baseline.json по текущей сборке
git diff frontend/e2e  # прочитать: каждая строка «-» — что-то исчезло или переименовано
```

Ревьюер смотрит дифф снапшотов так же внимательно, как код. Исчезнувшая строка без объяснения в описании PR —
повод не апрувить. Новое нарушение axe в эталон не добавляем — чиним.

## Перезапись фикстур

Нужна, когда страница начала запрашивать новый адрес (тест пишет «GET without a fixture») или добавлена страница.
Скрипт `frontend/e2e/record-fixtures.mjs` в CI не запускается.

1. Поднять бэкенд локально на SQLite во временной папке (`D:\Projects\_tmp\sinhrm\<папка>\`):
   `.env` с `DB_CONNECTION=sqlite`, `SANCTUM_STATEFUL_DOMAINS=127.0.0.1:4317` (или ваш `E2E_PORT`), `php artisan migrate`,
   все шаги `DemoDataService` (как ops `demo-fill`), `php artisan serve --port=8017`.
2. Сделать сессию демо-пользователя с ролями superadmin + hr_manager **локальным скриптом во временной папке**
   (через `session()` и `encrypter` приложения) и сохранить `{"name": …, "value": …}` в `session.json`.
   Обходов входа в репозитории и маршрутах нет и не будет.
3. `npm run build`, затем `SINHRM_SESSION=<путь>/session.json npm run e2e:record`
   (`RECORD_ONLY=<id страницы>,…` — дописать только эти страницы).
4. Скрипт обрезает списки до 30 строк и заменяет всё не синтетическое (e-mail вне `@sinhrm.test`, локальные адреса,
   аватары, пути к файлам, поля-секреты). Проверьте дифф глазами, затем `npm run e2e:update`, удалите временную папку.

## Правила для PR с рестайлом

1. `ui-parity` должен быть зелёным. Пока это не обязательная проверка, но рестайл с красным `ui-parity` не мержим.
2. Снапшоты инвентаря в таком PR не меняются. Если меняются — в описании PR объяснено каждое изменение.
3. Перенести кнопку можно; сменить её подпись, спрятать в меню без доступного имени или выключить — нельзя без
   отдельного решения.
4. Число нарушений axe не растёт (контраст в тёмной теме — частая причина).
5. Новое исключение в `layout-allowlist.json` — только с объяснением в PR, почему обрезка задумана.
6. PR заявлен как «пиксели не меняются» — приложите прогон `npm run e2e:visual`: на `main` один раз
   `npm run e2e:visual -- --update-snapshots`, затем на ветке `npm run e2e:visual` (эталоны в `e2e/.visual/`, не коммитятся).

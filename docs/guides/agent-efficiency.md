# Экономия контекста и проверок

## Работа агента

1. Держи один текущий результат в контексте задачи. Новая самостоятельная фича получает отдельную ветку и узкое задание; завершённую историю не переноси целиком. Для незавершённой задачи сначала используй её состояние на диске.
2. Перед planning/resume прочитай обязательные правила, `## Стан` своей задачи и только относящиеся к изменению исходники/документацию. Найди KB по конкретной теме; отсутствие результата не блокирует разрешённую работу. Уже прочитанные неизменные файлы повторно целиком не загружай.
3. Ограничь задание субагенту: цель, ответственность за файлы, worktree/ветка, ограничения, критерий результата и ссылки. Укажи, что другие агенты работают рядом и их правки нельзя отменять. Полную переписку передавай только при доказанной необходимости.
4. Простое чтение выполняй без отдельного агента. Для поиска и реализации используй согласованную недорогую модель, сейчас Luna. Сложные решения разбивай на небольшие проверяемые шаги; независимая проверка безопасности/архитектуры и final diff остаётся за Astra.
5. Запускай независимое ревью на конкретном сохранённом SHA с определённой целью. После изменения проверенного кода проверь новую delta и затронутые риски; прежний PASS не распространяется автоматически на новый head.
6. На границе этапа и перед handoff обнови `## Стан`. Он содержит worktree/ветку, base/head SHA, что сделано, evidence, следующий шаг и блокеры. Отдельная задача не получает общий смешанный статус соседних работ.

## Вывод инструментов и тесты

- Используй узкие `rg` запросы, выбранные строки/файлы и краткие CI summaries. Полный лог сохраняй вне репозитория только когда он нужен для диагностики; в контекст возвращай ошибку, итог и путь. Секреты/реальные персональные данные туда не копируй.
- Во время исправления выполняй минимальные проверки изменённого поведения согласно [development.md](development.md). Полные suites — в CI. Успешные обязательные проверки должны относиться к финальному shipping head.
- Повторяй проверку при новом изменении, сбое или конкретном оставшемся риске. Не запускай второй такой же прогон без причины. Новые/изменённые поведения сохраняют требование meaningful tests.
- Docs-only правка не требует придуманного теста, повторяющего её текст. CI/docs/worklog и независимая проверка достаточны при отсутствии изменённого поведения.
- CI, routing, auth и security configuration проходят соответствующие проверки: принадлежность файла к «конфигурации» не разрешает skip.
- Final review проверяет committed diff от фактической target/base ветки, staged/unstaged изменения и untracked файлы, а также GitHub head. Обычный `git diff` не является полным доказательством review.
- Форматирование выполняй после законченного изменения и учитывай его delta. Автоматические Claude hooks, `--fix` после каждого редактирования и тяжёлый анализ после каждого файла не входят в этот процесс.

## Состояние задачи

В существующем `docs/tasks/<task>*.md` поддерживай краткий блок:

```md
## Стан
- Час: YYYY-MM-DD, timezone.
- Worktree / branch / base SHA / head SHA:
- Текущий шаг:
- Сделано / evidence: CI run, exact reviewed head, live proof где требуется.
- Следующий шаг:
- Блокеры:
```

Временная граница восемь часов или час перерыва не требует сброса автоматически. При смене темы или лишней истории заверши текущий шаг, сохрани состояние и продолжи с узким контекстом; не создавай новый пользовательский чат без просьбы владельца.

## Что измеряем

Ledger агентов остаётся вне репозитория, как установлено `CLAUDE.md`. Если доступны, записывай input/cached/output tokens, число вызовов и источник измерения; недоступные значения — `n/a`. Размер Markdown, cache reads и длительность сессии сами по себе не измеряют недельный лимит и не доказывают экономию. Начни со сравнения нескольких сопоставимых задач.

Эти правила не меняют глобальный Codex config, размер окна, порог сжатия или hooks. Число 200K из Claude-процесса не принимается здесь за проверенный оптимум. Настройка клиента требует отдельного измеримого изменения; текущая задача вводит проектный порядок работы.

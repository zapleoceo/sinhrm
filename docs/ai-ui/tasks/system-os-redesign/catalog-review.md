## Required corrections

1. **Explicit core-module null is discarded by the auxiliary guard.** In auth.guards.ts:49, `windowModule ?? module` falls through when the generated metadata deliberately contains `windowModule: null`. Most newly registered core routes have no legacy `module` property, so branchModule becomes undefined and line 50 rejects them. Examples include docs, status, admin/users and admin/integrations; authenticated users with otherwise valid roles cannot open them in a window. Preserve an explicitly present null while rejecting missing/invalid metadata. Test a real generated core route metadata shape plus role denial. Current guard fixture only registers old Tasks `module: null`, so its PASS does not cover catalog core routes.

2. **Canonical Router navigation ignores window query replace/merge semantics and can import primary filters.** WindowNavigation.createUrlTreeFromCommands first creates a root Router tree and passes it to routeTreeForUrl. That method unconditionally merges the existing slot query (line 295) with the already root-processed query. A bare `/people` link retains prior window filters instead of resetting them. With primary `?name=Primary`, window `name=Window`, a scoped canonical navigate(['/people'], { queryParams: { sort: 'id' }, queryParamsHandling: 'merge' }) uses root merged name=Primary and overwrites the window filter. Apply query handling against the current *slot* namespace, respecting replace/default, merge, preserve and null clearing; do not seed from unrelated primary query. Test the actual scoped Router/RouterLink entry paths, not only createWindowTree directly. Independent production-method transpile reproduction using Angular DefaultUrlSerializer is at D:/Projects/HRM/tmp/browser-os-route-catalog/independent-query-repro.cjs: bare canonical result contains wq_name=Window; root-merged canonical result contains wq_name=Primary and wq_sort=id. This is source-level reproduction, not browser proof.

3. **Query subscriptions outlive their routed page after the adapter moved to the host.** OsWindowHost now provides WindowQueryState once for the persistent slot. Its watch() binds all subscribers to the adapter's own DestroyRef (window-query-state.ts:21), which is the host lifetime. TableUrlState.watch and windowAwareQueryParamMap delegate page callbacks to it. Replacing child routes inside an open slot therefore retains earlier page/table callbacks and captured signals until the slot closes, accumulating across navigation. Bind each watch subscription to its consumer lifetime (pass a consumer DestroyRef or return/register cleanup), while keeping the host context reusable. Add repeated route replacement coverage that observes subscription disposal/bounded live observers, not merely component ngOnDestroy calls.

4. **Four outlet capacity is not matched by four-slot chrome.** WINDOW_SLOTS contains os1–os4, but shell.layout.html:495 only assigns positional classes for os1/os2; shell.layout.scss:390–392 only supplies those normal geometries. os3/os4 have no bounded normal dimensions/insets. Minimized os2/os3/os4 all occupy the same bottom-right rectangle, hiding one another's restore/close controls. Derive normal and minimized positions from all slots, or make the reviewed geometry port an explicit prerequisite that fixes both states before publication as a usable four-window candidate. The parallel geometry implementation's normal defaults alone do not fix its similarly two-slot minimized offsets. Test/render all four windows and all four minimized controls at desktop/mobile widths. The current four-window RouterHarness fixture supplies outlets without actual shell chrome, so it cannot prove this.

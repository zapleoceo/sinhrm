## Batched P2 findings

1. **Workspace bounds follow tall page content, not visible viewport.** OsWindowWorkspace measures layer.clientWidth/clientHeight, while .window-layer is absolute and inset within shell content. Its containing content can be much taller than viewport (Overview, People/Reports lists). Geometry clamps to that long document extent; titlebars can be dragged far below the visible viewport, and mobile full-area window can inherit full page height. This does not meet viewport-safe chrome. Bound the workspace using the actual visible viewport minus system/Dock safe area, retaining correct local coordinate conversion and scroll handling. E2E currently compares windows against the same layer, so it would pass even if the layer is thousands of pixels tall. Add tall primary-content test asserting title/controls/window bounds against browser viewport, including scrolling, resize and mobile.
2. **Pointer termination omits final delta and capture-loss cleanup.** endGesture clears gesture and releases capture without applying pointerup client coordinates; final placement depends on the last pointermove, not final release. No lostpointercapture handler exists, so losing capture externally leaves the stored gesture active; a later move with matching pointerId can keep mutating stale state. Apply the final valid pointerup position before clearing; handle pointercancel/lost capture explicitly and ensure destroy/second-pointer cleanup is deterministic. Tests must include pointerdown→pointerup at a new position without a final move, capture loss followed by further pointer movement, and cancel preserving the chosen documented final state. Do not navigate or persist form data for these operations.
3. **Minimized/maximized titlebar can mutate restore geometry.** startMove and moveByKeyboard only gate narrow/button/target, not current view.minimized/maximized. The titlebar remains present in those states, so pointer dragging or arrow keys silently change the stored geometry even though inline geometry is not applied until restore. This violates retaining normal geometry through min/max and makes restored placement surprising. Disable movement/resize geometry updates for min/max views (focus/restore controls remain functional), and test gesture/arrow attempts in each state followed by restore retaining prior bounds.

2. **P2 — focusPrimary cannot select primary while any unminimized window exists.** `window-navigation.ts:56–58,109`: focusPrimary clears osActive, but windows() interprets absent active as the first unminimized open slot. The mobile “show primary” button therefore retains an active auxiliary window and keeps primary hidden/inert. Distinguish explicit primary focus from missing/invalid initial focus. Test one open unminimized window→focusPrimary→activeSlot null with same window instance retained, then restore/focus auxiliary; current unit only calls focusPrimary after minimizing the sole window and misses this case.
3. **P2 — launcher cannot restore an already minimized singleton.** `window-navigation.ts:72`: open finds existing route then calls focus(existing), which returnsfalse for a minimized slot at104. Clicking “open Tasks/People” leaves its minimized window unchanged. Existing singleton open should restore+focus it, without new page construction/query reset. Test minimize→launcher open and instance identity/query retention.
4. **P2 — permission/identity changes do not invalidate retained views.** WindowNavigation observes Router NavigationEnd only, not auth.user identity/roles/modules. Already mounted/minimized People remains alive and can be restored while launcher is hidden; Angular guards do not automatically rerun for a retained unchanged route. Add explicit lifecycle handling keyed to actual identity/security scope and current permission: destroy/clear unauthorized retained views and prevent restore/action races, including minimized views. Do not claim API bypass; server still authorizes requests, but stale sensitive page state remains in memory/UI. Test real signal change/reload/revoked module, identity clear/replacement and role narrowing with both slots live; avoid broadening hasModule's guest semantics. Clearing security-invalid views must not be blocked by a dirty form belonging to the prior identity.
5. **P2 — unrelated window/focus navigation drops queued table edits.** `frontend/src/app/core/ui/table/table-url-state.ts:69–76` remains subscribed to every global NavigationStart and unconditionally drops pending edits. The facade deliberately keeps real global events. Typing a debounced People filter, then focusing/minimizing another window or changing another table before its delay expires cancels the typed edit. Introduce window-aware cancellation through the table adapter: cancel on genuine navigation replacing/leaving this table or deliberate Back behavior, not unrelated branch/control changes. Preserve existing primary semantics. Test queued edits with other-slot write/focus/minimize and same-table leave/Back cancellation; assert eventual value/request and no stale navigation.
6. **P2 — mobile inactive window chrome remains focusable.** `frontend/src/app/features/shell/shell.layout.html` inactive article gets aria-hidden=true/mobile-inactive, but no matching CSS hides the article and no article-level inert is set. Only its body is hidden/inert. Header tabindex0 and controls remain in keyboard order under aria-hidden and can receive focus behind the active window. Hide/inert the whole inactive expanded article on mobile, while retaining an accessible separate restore/switcher path and legitimate minimized controls. Preserve component instances. Test keyboard traversal/focus, primary switching and two live expanded windows at390/375px; no focusable descendant under aria-hidden.

## Decision for Luna now

Proceed with preferences, v5 material tokens and shared component/page styling across the real system **while retaining the primary RouterOutlet and existing routing**. Theme/color/style/transparency/reduced-motion/performance are foundation scope. Preserve every existing control and form. Do not label an active-route wrapper with decorative inactive windows as simultaneous module windows.

Implement true multiwindow in the next bounded bridge round using a small fixed set of **named RouterOutlets containing existing routed pages**. Initially primary + two literal named slots (`os1`, `os2`), not an unbounded dynamic outlet registry. Enable only audited route families. Unsupported routes continue through the primary route normally. Expand compatibility family by family; user authorization covers this staged work, and no new approval question is needed. Full multiwindow for every current page is not a safe single shell-template change.

## Minimal next route bridge

1. The original guards still execute through Router navigation; use no manual guard invocation or synthetic ActivatedRoute.
2. Add explicit typed `data.module` metadata for copied route families, derived from the existing module mapping and tested for parity. Refactor moduleGuard to derive the target module from the actual branch snapshot/metadata, never another outlet's global URL. Keep roleGuard, server authorization and disabled-module behavior. Reject unmapped auxiliary route registrations by default; core/null classification must be deliberate. On account/active-role/module permission changes invalidate unauthorized windows immediately, not merely on the next navigation. Inactive pages otherwise remain alive without rerunning guards.
3. Add `WindowNavigation` with a validated window/route registry. It builds UrlTrees updating only its assigned outlet and preserving other branches; close clears that outlet through the Router (thus canDeactivate), minimize only changes visibility and retains the instance. Store UI state only after NavigationEnd; NavigationCancel/Error restores the prior UI and no empty phantom window survives. Route singleton identity includes concrete route/entity parameters, not only module name. Primary existing URLs remain valid; workspace auxiliary URLs share the actual open branch paths. A reserved validated active-slot URL parameter may identify focus; test collisions and strip it from application query state. Back/Forward reconstructs workspace from successful Router state rather than reopening stale registry entries.
4. For pilot pages use explicit window-aware links/navigation calls. Keep native href/open-in-new-tab behavior meaningful. Do not provide a fake Router service or blanket rewrite absolute URLs. A link intentionally leaving the workspace (logout/public URL) retains its meaning. Focus inactive window before its navigation; ensure title/group and focus management select the active branch, not root.firstChild alone.
5. Introduce `WindowRouteState` as an application adapter, **not an ActivatedRoute replacement**. Primary reads/writes existing query params unchanged. Auxiliary supported filters use outlet-scoped matrix params with a validated prefix/codec (or equivalent explicitly namespaced URL state); route id params remain untouched. TableUrlState/ClientTable gain an injected adapter with existing primary behavior as default. Auxiliary consumers must opt in before registration. Avoid global query changes silently reloading other windows; tests must include two tables with different filters and queued edits. Shared ActivatedRoute query params cannot be isolated by DI alone.
6. Define a per-window activity signal/context. Only allowlist pages without ongoing background work or adapt their recurring work to visibility/activity using switchMap/EMPTY and DestroyRef cleanup. Pause recurring refresh while minimized; let explicitly started finite user jobs follow a documented policy. Close destroys route view via normal Router outlet lifecycle. Keep active/mounted window count bounded and don't auto-create all modules. Mobile shows one active view with inactive views inert/hidden; no focusable hidden controls.
7. Unsaved form safety: changing focus/minimizing does not remove its branch, so canDeactivate does not run and data remains. Replacing or closing that branch and browser Back removing it run its existing guard. Cancel keeps route/geometry/focus/form unchanged. No silent eviction of dirty forms. Hard auth/session invalidation must destroy sensitive views and subscriptions after any deliberate logout flow; don't let a stale minimized guard preserve data after identity changes. Persist only permitted cosmetic geometry/preferences per user, never form values/page instances/entity payloads.

## Public APIs considered

Named outlets are the preferred first bridge: Router creates real components with their matched ActivatedRoute, input bindings and injector contexts, and owns guards/destruction. Outlet names are literal/stable. [Angular named-outlet guide](https://angular.dev/guide/routing/show-routes-with-outlets).

RouteReuseStrategy alone caches an inactive subtree; it does not display multiple routed views or pause background work. DetachedRouteHandle is opaque: never cast to guessed componentRef/contexts fields. Angular22.2 provides public destroyDetachedRouteHandle for disposal, but a reuse strategy still needs tested semantics for dirty navigation, auth invalidation, query state and eviction. Use it later only for a demonstrated cache requirement, not as a shortcut to simultaneous pages. [Public disposal API](https://angular.dev/api/router/destroyDetachedRouteHandle).

RouterOutletContract/RouterOutlet public detach/attach return component references and permit a deliberately engineered outlet implementation, but transferring views/child outlet contexts and maintaining the router's single active branch is substantially more complex than fixed named outlets. CDK portals can render views, not establish a guarded matched route tree; a ComponentPortal of an existing page bypasses the navigation contracts unless the Router remains owner. Do not implement either as the initial bridge. [RouterOutletContract](https://angular.dev/api/router/RouterOutletContract).

Angular explicitly documents query params as shared by all routes, whereas route params belong to a route. This is the reason for the application state adapter, not speculation. [ActivatedRoute API](https://angular.dev/api/router/ActivatedRoute).

## Addendum — scoped Router navigation facade feasibility (2026-10-30)

**Conditional GO for a bounded pilot; not a promise to eliminate all69 call-site migrations.** This refines the earlier blanket rejection of a fake Router: a wrapper-scoped navigation facade can delegate actual navigation to the root Router and retain genuine routed components/guards. It must not fabricate ActivatedRoute/router state or dynamically create pages. Foundation remains primary-routing-only until bridge tests pass.

Verified installed `frontend/node_modules/@angular/router/package.json` version22.2.1 and its actual source: `_router-chunk.mjs` RouterOutlet.activateWith at1509 creates an OutletInjector using the real ActivatedRoute, child contexts and outlet ViewContainerRef's location.injector. OutletInjector at1612 overrides only ActivatedRoute, ChildrenOutletContexts and ROUTER_OUTLET_DATA; other tokens delegate to its parent. Consequently, a **component-level** Router provider on a real routed OsWindowHost containing the child outlet is inherited by child pages/RouterLinks. A route-level environment provider is not equivalent: keep the facade out of route environments used by guards. Factory uses the ancestor/root Router with skipSelf, never recursively injects its own Router. Root/route environment services and guards keep their actual root Router; test that explicitly. Preserve normal RouterOutlet and withComponentInputBinding.

Installed `_router_module-chunk.mjs` RouterLink at393 calls injected Router.createUrlTree; computeHref at411 uses serializeUrl and LocationStrategy. A plain click at378 calls navigateByUrl with that tree; Ctrl/Meta/target/new-tab uses the native href. A RouterLink given an existing UrlTree bypasses createUrlTree. Therefore facade createUrlTree must return a **real workspace UrlTree**, and facade navigateByUrl must recognize an already-workspace tree without wrapping its branch twice. Do not return a canonical-only tree for href and translate only clicks: that breaks new-tab/share/reload. Do not use private tree markers/route internals; use public UrlTree segment groups/outlets and a precise validated canonical/workspace input policy. Reject ambiguous unregistered workspace targets rather than silently rewriting another slot.

Bounded supported facade contract:

- Typed WindowNavigation owns canonical-to-assigned-slot UrlTree mapping and query namespace codec. Proxy may serve existing Router injection sites as an adapter, but new code uses this explicit service. Access delegated getters with the root as receiver and bind delegated methods to the root; never proxy private implementation fields or clone Router state.
- Override createUrlTree/navigate/navigateByUrl/isActive consistently. Respect relativeTo:null versus an actual branch route, ../, matrix parameters, query replacement/merge/preserve, fragments and NavigationExtras replaceUrl/skipLocationChange/state/info/browserUrl. Public/root destinations such as /login and intentional primary/workspace navigation need an explicit escape policy. A facade cannot infer the intended destination semantics of every existing absolute navigation.
- Root Router remains the sole navigation engine; createUrlTree/navigate calls ultimately use its public methods and guards. Do not invoke guards manually, swallow cancellation, or convert guard redirect UrlTrees inside the scoped facade. Authorization still requires branch-derived moduleGuard metadata and role/module invalidation described above.
- A canonical facade url together with globally delegated routerState/currentNavigation/events is **not** a fully transparent Router. Do not synthesize/filter events casually: NavigationStart cancellation is already consumed by TableUrlState, RouterLinkActive watches NavigationEnd/navigated, and public navigation promises must retain Cancel/Error/Skipped semantics. Prefer retaining actual root events and using a separate explicit per-window event/state adapter for consumers that require scope. If events are projected, retain event types/IDs/terminal outcomes and prove each consumer contract; no arbitrary event-shaped objects. Document routerState as global; consumers requiring a canonical branch must use WindowRouteContext rather than a fabricated RouterState.
- Namespace writes alone do not isolate direct ActivatedRoute.queryParamMap reads or withComponentInputBinding's query inputs. Keep a real ActivatedRoute, adapt TableUrlState/ClientTable and the previously identified direct readers to WindowQueryState, and check relevant input-binding collisions. Root-provided services may inject the root Router even when invoked by a window page: the facade cannot automatically scope them, MatDialog-created components, or services created by route EnvironmentInjectors. Audit these and retain explicit navigation at exceptions.

Required proof before widening beyond pilot (targeted Router/TestBed integration; no local app server needed):

1. Two real wrapper outlets inject distinct facades into page, page-provided service and RouterLink while child ActivatedRoute/input IDs are genuine; guard/root singleton inject the root Router. Confirm dialogs and route providers have their documented injection context.
2. Absolute and relative links, Router.navigate and navigateByUrl(string/UrlTree), prebuilt UrlTree RouterLink, primary/public escape, named-outlet trees, query/matrix/fragment options and native href/new-tab all reach the intended branch once without modifying the other slot.
3. RouterLinkActive/isActive, root Router navigation events and navigation promises agree on successful/rejected/redirected/skipped navigation; no double translation, duplicate history, phantom window or cancellation loss. Back/Forward and direct pasted auxiliary URL restore route/focus correctly.
4. Two query tables retain independent state under merge/replace/preserve and delayed writes; actual direct readers/input binding see their intended values. Editing one window must not trigger the other page's reload or cancel its queued write merely due unrelated global NavigationStart.
5. Existing module/role guards and vacancy canDeactivate still run for real close/replace, not focus/minimize; cancellation preserves forms. Preserve lifetime/polling/auth-clear gates from the main report.

Decision: build the facade as an opt-in tested adapter for fixed-slot real-router hosts, then count which existing calls work unchanged. It can substantially reduce RouterLink/programmatic call-site changes, but a blanket Proxy forwarding all remaining members does not establish semantic compatibility for all pages. No private DetachedRouteHandle access, synthetic Router tree, fake ActivatedRoute or guard bypass is required or approved. No code or tests executed in this preflight; source inspection only.
